1. 引言

1.1 编写目的

本文件定义 FICC 销售智能交易平台中报价录入、行情中心、报价管理三个模块的完整业务需求。文档面向业务人员、产品经理、交互设计人员和研发人员，说明每个页面应呈现的业务场景、信息布局、数据列表、交互动作、反馈规则和异常处理。

1.2 业务背景

债券报价来自交易员沟通、下行消息和人工输入等多种场景。报价具有时效性、双边方向、价格口径、报量、清算方式和人员归属等复杂要素。平台需要将零散报价转化为可复核、可查询、可筛选、可维护的业务信息，并让交易员能在同一工作台完成报价确认、行情发现、机会跟进和日内复盘。

1.3 建设目标

  1. 缩短报价从接收、识别、人工确认到进入行情的路径。
  2. 让交易员按信用债、利率债、债券条件、报价条件和关注条件快速定位机会。
  3. 清楚区分正式报价、待确认报价和模糊报价，避免未确认内容影响行情。
  4. 让报价的创建、修改、撤销、恢复和删除具有明确业务边界和可追溯结果。
  5. 让页面中的列表字段、按钮状态、筛选结果和反馈文案保持一致、可理解、可操作。

1.4 适用范围

本文件覆盖以下页面：

  1. 报价录入：报价确认、精确报价、模糊报价。
  2. 行情中心：信用全部、信用最优、利率全部、利率最优、模糊报价、报价提醒、统一筛选、债券详情与右侧行情面板。
  3. 报价管理：今日报价、历史报价。

1.5 术语与业务对象

待确认报价：已接收或已识别、尚未由交易员确认的报价候选。

正式报价：经交易员确认后生效的报价，可进入有效行情。

模糊报价：交易员输入非标准格式或条件型报价文本后，经系统识别和用户确认形成的报价草稿；用户确认后可转为正式报价进入行情。

Bid：买入方向报价。

Ofr：卖出方向报价。

Refer：撤销有效报价，使其退出有效行情。

Unrefer：将已撤销报价按业务规则恢复为新的有效报价。

报价方式：QT、ideal、手工录入等报价来源/录入方式。

报价所有者：对报价承担业务归属的内部交易员。

实际操作人：实际执行录入、确认、撤销或代办操作的人员。

精确报价：包含明确债券代码或简称的报价文本，系统可直接识别债券身份并补全报价要素。

债券筛选：基于模糊报价识别的条件，从本地债券池中匹配候选债券的过程。

最优报价：同一债券、同一方向、同一价格口径和清算条件下，价格最优的报价（Bid取最高可比值，Ofr取最低可比值）。

DM（Data Master）：外部债券数据服务，提供债券基础资料、估值、收益率曲线等数据。

剩余期限：债券距离到期日的剩余时间，以年为单位展示，如7.71Y、2.50Y。

债券详情面板：行情中心右侧随选中债券展示的盘口、估值、机构报价和智能推荐信息面板。

3. 报价录入

3.1 模块说明

报价录入模块承接下行报价、精确报价和模糊报价的识别与人工确认流程。模块页面采用“输入/批次区域 + 待确认数据列表 + 编辑与批量操作区 + 确认结果反馈”的工作模式。任何识别结果都必须由交易员复核；只有通过确认的内容才可成为正式报价。

3.2 报价确认

3.2.1 业务场景

交易员收到来自QT、ideal等来源的下行报价后，需要按批次查看原始内容和已识别报价行，修订错误或补全缺失字段，确认后将可用报价发布至行情中心。

操作路径：收到报价提醒 → 打开报价确认页 → 选择批次查看原文和识别结果 → 逐行核对债券、方向、价格、报量、清算方式 → 修正错误字段 → 批量或逐条确认 → 成功行进入有效正式报价，失败行保留待处理。

业务价值：将外部来源的非结构化报价快速转化为系统内的正式报价，同时保留人工复核环节确保数据准确性。

3.2.2 页面布局

  1. 顶部工具栏：刷新、批次筛选、批量属性、确认报价、取消待确认报价和结果提示；批量操作按钮最右侧提供“模拟”按钮，仅在非生产环境显示。
  2. 左侧/上方批次区：按来源机构和接收时间展示待处理批次；每个批次显示来源、机构、接收时间、条数、已选数量和异常数量。
  3. 中部原文区：展示选中批次的原始内容摘要，支持展开查看。
  4. 下方数据列表：展示该批次全部待确认报价行；支持行勾选、行内编辑和批量处理。
  5. 右侧/底部结果区：显示本次确认成功、失败、待补充和已取消的处理结果。

3.2.3 操作与反馈

  1. 选择批次：点击批次后加载该批次原文和数据行；切换存在未保存编辑时，提示“当前修改尚未保存，是否继续切换”。
  2. 选择行：支持单选、全选本批次和取消全选；批次头显示“已选择 X/Y 条”。
  3. 行内编辑：点击可编辑字段进入编辑状态；失焦或回车后校验格式。校验失败时保留输入并标红字段。
  4. 批量属性：选择多行后可设置方向、清算速度、标签和备注。页面必须先预览受影响行数；已有值默认不覆盖，勾选“覆盖已有值”后才覆盖。
  5. 确认报价：未选择行时按钮不可用；点击后展示确认摘要。成功行进入有效正式报价，失败行保留在当前批次。
  6. 取消待确认：仅取消待确认行，不影响任何已经确认的正式报价；操作后列表显示取消结果。

  2. 同一行的价格类型与价格必须成对存在；不同价格类型不得混用。

3.3 精确报价

3.3.1 业务场景

交易员将格式相对明确的文本、表格或图片中的报价内容录入页面。系统按行拆分并识别要素（债券代码/简称、方向、价格、报量、剩余期限等），交易员在结果列表中复核、修改和确认。

操作路径：进入精确报价页面 → 粘贴报价文本 → 点击"识别" → 系统逐行解析并匹配债券 → 识别结果进入待确认列表 → 交易员核对、修订 → 确认发布正式报价或保存为模糊报价草稿。

业务价值：支持交易员从聊天记录、邮件、Excel等来源快速录入精确报价，系统自动识别债券身份和报价要素，大幅减少手工录入和查找债券的时间。

3.3.2 页面布局

  1. 顶部输入区：报价文本输入框、粘贴入口、清空、识别、保留原文设置；截图识别、导入图片、导入表格入口已在界面隐藏（能力保留）。
  2. 输入辅助区：展示识别提示、失败行数和原文保留状态。
  3. 识别结果列表：按行展示识别结果，可勾选、编辑、删除或批量补充字段。
  4. 底部操作区：批量编辑、确认报价、保存为模糊报价草稿和处理结果提示。

3.3.3 操作与反馈

  1. 粘贴：支持多行内容；识别前保留输入内容。内容为空时“识别”按钮不可用；截图识别、导入图片、导入表格入口界面隐藏（能力保留）。
  2. 识别：开始后按钮显示处理中；完成后显示“共识别 X 行，其中 Y 行待补充”。
  3. 表头识别：首行包含代码、简称、报价、报量、期限、评级或估值等字段时，系统将其作为表头候选；用户可调整“报价”“报量”列含义。
  4. 行编辑：用户可修正任何可编辑业务字段；行内冲突必须紧邻字段显示。
  5. 删除候选：删除前提示“仅删除本次待确认候选，不影响已发布报价”。
  6. 保存为模糊报价草稿：当用户不准备形成正式报价时，可将原文和已识别条件保存至模糊报价页面。

3.4 模糊报价

3.4.1 业务场景

操作路径：进入模糊报价页面 → 输入条件型或非标准文本 → 点击"识别" → 系统识别方向、品种、筛选条件 → 识别结果进入左侧数据列表 → 用户点击报价数据查看右侧债券候选 → 确认后可转入精确报价发布或保存为模糊报价草稿。

4.7.1 业务范围与当前数据架构

4.7.2 提醒类型与触发条件

提醒类型触发条件不参与判断的条件关闭开关后的行为
关注债券开关开启；active正式报价的标准债券代码命中当前账户任一已保存关注债券分组。所有关注分组均参与，不要求该分组正在左侧激活。报价所有人、方向、价格、报量、计价方式和清算速度不限制。立即从当前提醒投影移除该类型；后续不弹出该类型新提醒。

对价提醒开关开启；两条active正式报价债券代码相同、方向相反，并且一条属于当前用户、另一条属于非当前用户。不判断两边价格是否相等、倒挂或达到成交条件；不限制价格类型、清算速度、价格、报量、机构或交易员。立即移除当前对价提醒并停止新增弹窗。

4.7.3 报价变化与实时重算

  1. 正式报价新增、编辑或Unrefer恢复：服务端更新live_quotes并写quote_events，通过SSE向各账户发送经过字段权限投影的报价；前端按quoteId和stateRevision合并后重建全部行情、最优行情和提醒。
  2. Refer撤销或删除：关联报价不再参与active集合，对应关注、筛选、对价和最优提醒立即移除或按剩余报价重算。
  3. SSE事件重复、乱序或revision回退时不重复处理；发现版本缺口时执行全量快照恢复。SSE断开后每5秒使用全量报价状态轮询，成功后重新建立一次性票据连接。
  4. 初次登录和不带notify的手动刷新只建立当前提醒列表，不弹出历史存量；只有已存在快照之后检测到的新alertKey才弹窗。

  2. 同一债券同时命中关注债券、筛选分组和我的最优时，在提醒列表合并为一行，以斜杠展示完整类型集合并合并分组名称；对价提醒保留独立行。
  3. 列表按报价更新时间、报价时间、来源时间倒序；未读角标按当前提醒行统计，合并后的多类型行计1条。

  1. 新提醒在页面右下角展示；同一显示类型只保留一个弹窗，新事件到达时更新其内容。多个类型可纵向堆叠，弹窗区域最高为视口80%并可滚动，不自动消失。
  2. 弹窗头部显示提醒类型和本次新增数量；正文最多展示本次该类型最近3条，内容包括剩余期限、代码、简称、报价时间，以及Bid/Ofr双方的内部归属交易员、报量、价格类型、价格和报价操作标签；缺失侧显示--。

  4. “查看”只将当前弹窗包含的alertKey标记为已读，关闭该弹窗，切换到行情中心报价提醒页签，并选中、滚动定位和高亮第一条对应债券；不得顺带清除其他弹窗或其他未读提醒。
  5. “关闭”只关闭当前弹窗，不写已读、不清除导航及页签角标。关闭后相同alertKey不重复弹出，但仍保持未读并可在提醒列表查看。

4.7.7 已读状态、权限与失败恢复

  1. 已读状态以account_id＋alertKey隔离并幂等保存，后端默认保留180天；不同账户查看同一报价互不影响。
  2. 前端先更新本账户角标，再调用POST /api/alerts/read-state/bulk批量保存；失败键进入当前账户本地待同步队列，登录加载已读状态后自动重试。GET /api/alerts/read-state失败时保留本地已读集合，不得清空业务列表。
  3. 服务端向每个SSE连接按查看账户过滤字段。普通交易员查看他人报价时，对手机构、对方交易员和备注为空；内部报价归属交易员仍按公开报价归属展示。
  4. 提醒开关和分组按账户保存，使用revision防止并发静默覆盖；保存冲突时重新加载服务端配置并提示用户。

4.7.8 当前限制与后续增强

  1. 当前没有提醒业务事实和历史查询接口，board_alert表不作为当前提醒数据源；如需历史提醒，应新增服务端提醒事实记录，保存账户、类型、alertKey、触发报价版本、触发快照、产生/失效时间和失效原因。
  2. 当前没有逐条已读、全部已读按钮、系统级通知或声音提醒；后续新增时必须保持账户隔离并提供独立开关。
  3. 对价提醒是“同券反方向匹配”，不是成交机会判断，不得在文案中宣称价格相等、倒挂或可成交。

  2. 核心指标展示最新成交、时间、昨收、高、开、低、久期及估值；缺失字段显示"--"。
  3. 机构筛选默认"全部"；点击机构标签后仅展示该机构报价，再次选择"全部"恢复。
  4. 点击最优Bid或最优Ofr时，高亮机构报价明细中的对应方向。
  5. 机构报价明细无数据时显示"暂无盘口数据"。
  6. 点击收起按钮后保留当前列表和筛选状态；再次展开显示当前选中债券。
  7. 面板宽度支持拖拽调整；最小宽度不小于280px。

4.9.2 智能推荐模块

4.9.2.1 业务场景

智能推荐基于所有用户已确认的正式报价计算匹配结果。经用户确认的QT模拟下行报价与正常正式报价采用相同口径参与推荐；当前不启用推荐模拟兜底数据，系统也不增加推荐健康检查统计。

4.9.2.2 布局说明

  1. 推荐触发区：用户在行情中心选中债券并打开右侧详情面板后，系统自动加载该债券的推荐数据。推荐区位于行情小窗下方。
  2. 推荐方向标签：展示Bid和Ofr两个方向的推荐标签，点击切换查看对应方向的推荐列表。
  3. 推荐结果列表：展示当前方向的推荐结果，包含推荐得分、机构/交易员、债券、报价次数、最新报价/报量和内部归属交易员。
  4. 推荐依据区：每条推荐支持展开查看其报价证据；证据详情执行与列表相同的机构和交易员字段权限脱敏。
  5. 时间窗口区：支持预设或自定义历史窗口，自定义窗口最大365天。

4.9.2.3 推荐逻辑

  1. 推荐计算读取所有用户录入并确认的正式报价，不按录入人缩小候选数据范围；用户确认的QT模拟下行报价同样参与。
  2. 机构和交易员字段按证据归属控制：证据属于当前查看用户时显示机构和交易员姓名；非本人报价证据的这两个字段返回空值。
  3. 除机构和交易员外，推荐得分、债券信息、报价次数、最新报价、报量和内部归属交易员等字段可正常展示。
  4. 已撤销或已过期的历史正式报价可在用户所选时间窗口内作为历史证据，并按时间衰减计分；自定义时间窗口最大365天。
  5. 当前系统尚无带用户归属的真实成交事实存储；未来接入成交数据时，所有用户的成交均可参与计算，但机构和交易员必须沿用相同的本人可见、非本人置空规则。

5. 报价管理

5.1 模块说明与页面框架

报价管理用于处理已形成的正式报价。模块提供“今日报价”和“历史报价”页签。页面采用“顶部操作工具栏 + 查询条件 + 数据列表 + 状态汇总”的布局。

  1. 工具栏动作：Refer、Unrefer、删除、Copy、导出。
  2. 查询条件：代码/名称、报价机构、长城交易员、报价方式、报价状态；历史报价额外提供日期区间。
  3. 数据列表：展示报价状态、报价要素、参考信息和时间。
  4. 状态汇总：显示当前查询结果条数及有效、撤销等状态数量。

5.1.1 左侧筛选面板

报价管理的今日报价和历史报价页签共用左侧筛选面板。筛选面板按"报价条件、债券条件、人员与来源"三大分区组织，每个分区可展开/收起。已应用条件在面板顶部汇总展示，并提供单项移除和"一键清空"。

筛选分区与条件：

  1. 报价条件区：报价方式（QT/ideal/手工录入，枚举多选）、报价状态（有效/撤销/已删除，枚举多选）、方向（Bid/Ofr，枚举多选）、清算速度（T+0/T+1，枚举多选）、价格类型（到期收益率/净价/全价，枚举多选）。
  2. 债券条件区：产品分类（信用债/利率债/同业存单，枚举多选）、剩余期限（0-1Y/1-3Y/3-5Y/5-7Y/7-10Y/>10Y，枚举多选）、主体评级（AAA+/AAA/AA+/AA等，枚举多选）、债券评级（枚举多选）、债券库（在库/非在库，枚举多选）。
  3. 人员与来源区：长城交易员（联想选择，支持多选）、报价机构（联想选择，支持多选）、报价交易员（联想选择，支持多选）。

交互规则（与4.8.3统一筛选逻辑一致）：

  1. 同一条件多选为"或"，不同条件同时存在为"且"。
  2. 数值和日期范围包含边界；开始值大于结束值时，字段旁显示错误，应用按钮不可用。
  3. 条件不可用或无覆盖时，应展示原因，不得误显示为"无结果"。
  4. 应用后列表顶部显示"已应用 X 个条件，结果 Y 条"；清空后恢复默认结果。
  5. 今日报价默认筛选当前业务日；历史报价需额外选择日期区间。
  6. 筛选条件在今日报价和历史报价页签之间切换时保持一致（日期条件除外）。
  7. 筛选面板与右侧数据列表联动：应用条件后列表实时更新，清空条件后恢复默认排序。
  8. 已应用条件在面板顶部以标签形式汇总展示，支持单项移除和一键清空。

5.2 今日报价

5.2.1 业务场景

交易员查看和维护当前业务日的报价，快速定位本人报价，复制报价内容、导出当前可见结果或对符合状态的报价执行Refer、Unrefer和删除。

5.2.2 页面布局与交互

  1. 顶部操作栏从左到右显示Refer、Unrefer、删除、Copy、导出。
  2. 查询区支持代码/名称、报价机构、长城交易员的联想选择，以及报价方式、报价状态下拉选择。
  3. 未选中报价时Refer、Unrefer、删除、Copy按钮不可用；导出在当前无结果时不可用。
  4. 点击清除图标仅清除对应输入条件并立即更新结果提示。
  5. 状态动作执行前弹出确认信息：动作名称、选中条数、适用状态和不可逆提示。

5.2.4 状态动作规则

  1. Refer仅适用于有效报价。执行成功后，报价状态变为撤销并退出有效行情。
  2. Unrefer仅适用于已撤销报价。执行成功后形成新的有效报价，原撤销记录仍作为历史保留。
  3. 删除仅适用于已撤销报价；删除后不可恢复，不参与常规查询。
  4. Copy仅复制当前用户有权查看的报价信息；操作成功后提示“已复制 X 条报价”。
  5. 导出仅导出当前查询结果中用户有权查看的字段；无数据时提示“暂无数据可导出”。

5.3 历史报价

5.3.1 业务场景

交易员按业务日期复盘历史报价，查询当时的报价状态和信息，并在规则允许时对已撤销报价执行Unrefer或删除。

5.3.2 页面布局与交互

  1. 工具栏显示Unrefer、删除、Copy、导出；不提供对历史有效报价的Refer入口。
  2. 查询条件与今日报价一致，额外提供开始日期、结束日期和查询按钮。
  3. 默认日期为前一业务日，开始日期与结束日期相同。
  4. 用户修改日期或其他条件后，必须点击“查询”才更新数据；查询期间显示处理中。
  5. 开始日期晚于结束日期时，字段旁显示“开始日期不能大于结束日期”，查询按钮不可用。

5.3.3 数据列表字段

历史报价列表字段与今日报价一致，但不显示“报价状态”列。其余字段依次为：报价方式、剩余期限、代码、简称、方向、报价、报量(万)、操作、报价机构、报价交易员、长城交易员、最新成交价、债券库、主体评级、债券评级、中债净价、中债偏离、中债YTM(%)、中证净价、中证全价、中证YTM(%)、报价时间。

各字段格式、必填性、取值规则和交互与5.2.3对应字段一致；历史列表中的报价时间必须反映历史业务日，不能用当前时间替代。

5.3.4 历史业务规则

  1. 历史查询结果应反映所选业务日期内的报价事实；后续资料变化不得静默改变历史报价状态和报价要素。
  2. 已撤销历史报价可按权限执行Unrefer，产生新的有效报价；不得直接将历史记录改回有效。
  3. 历史结果为空时显示“暂无历史报价数据”；不得用空白页面替代提示。
  4. Copy与导出均以当前查询条件和用户可见范围为准。

6. 公共业务规则

6.1 权限与可见性

  1. 先判断用户是否可见，再展示数据、进行筛选、汇总、详情查看、Copy或导出。
  2. 报价所有者、实际操作人、报价机构、报价交易员、对手机构和对手交易员具有不同业务含义，不得相互代填。
  3. 管理员代办时，页面必须明确显示“报价所有者”和“实际操作人”，并记录代办原因。

6.2 报价状态与动作

  1. 待确认报价仅可编辑、确认或取消。
  2. 有效正式报价可进入行情、最优计算和提醒判断，可执行Refer。
  3. 已撤销报价不进入有效行情；可按规则Unrefer或删除。
  4. 已删除报价不可恢复，不参与任何常规行情和管理列表。
  5. 模糊报价独立于正式报价，不进入有效行情或最优计算。

6.3 字段空值、排序与时间规则

  1. 数值字段默认按数值排序；空值排在有值之后。
  2. 评级字段按业务评级顺序排序；未知评级单独归类。
  3. 日期时间以业务日口径展示；悬停或查看详情时显示完整日期、时间。
  4. 参考价格、估值和评级如不存在、未知或不适用，必须显示对应状态，不能以0、否或空白替代。

7. 账号与权限

7.1 账号来源

平台账号数据来源于STC系统，采用统一账号管理机制。

  1. 账号信息由STC系统统一创建和维护，包括账号ID、姓名、部门、角色等基础信息。
  2. 平台通过接口或同步机制从STC获取账号数据，不独立创建账号。
  3. 账号生命周期（创建、启用、停用、注销）由STC系统管理，平台实时同步账号状态。
  4. 账号停用后，平台立即终止该账号的所有会话和操作权限；已产生的业务数据保留不变。
  5. 账号信息变更（如角色调整、部门调动）在STC系统操作后，平台在下次登录或定时同步时生效。

7.2 权限管理

平台权限基于STC系统的角色和授权体系进行管理，支持按交易角色设置页面级、操作级和数据级权限。

角色定义：

  1. 交易员（Trader）：高频使用者，负责报价录入、行情查看和报价维护。默认可查看行情中心全部页面、报价录入全部页面和报价管理本人报价。
  2. 管理员（Admin）：负责账户管理、权限配置和运行异常处理。可查看全部页面，可基于角色授权处理他人报价。
  3. 技术人员（Technician）：负责系统健康检查和数据维护。默认只读权限，不可修改业务数据。

权限维度：

  1. 页面级权限：控制用户可查看的页面范围。例如：报价录入页面仅授权交易员和管理员访问；行情中心所有角色可访问；报价管理页面按角色配置。
  2. 操作级权限：控制用户在页面内可执行的操作。例如：Refer、Unrefer、删除、Copy、导出、发送等操作按角色和数据归属配置。
  3. 数据级权限：控制用户可查看的数据范围。例如：报价机构和报价交易员字段仅本人可见；管理员可查看授权范围内的他人报价。
