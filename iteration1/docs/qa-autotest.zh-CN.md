# QA 环境功能自动测试

API 调试器新增 **QA 自动测试** 页签，使用两个真实 STC 业务账号和用户选择的基础资料债券，验证报价生命周期、筛选查询、实时推送及四类提醒。原有客户端自动测试仍使用模拟账号和固定样例，接入真实 STC 时请使用本页签。

## 操作步骤

1. 启动 QA 的 QuoteSvr、NotificationSvr 和 GW，确认基础资料已同步、NotificationSvr 已连接 QuoteSvr。使用已完成 STC 登录修复的版本。
2. 打开 `Ficc.DpsApiDebugger.exe`，顶部填写 QA GW 地址、端口及第一个真实 STC 账号，连接 GW。
3. 切换到 **QA 自动测试**，填写第二个真实 STC 账号和密码。使用两个不同的专用、非管理员测试账号，运行期间不要从其他客户端登录这些账号或修改其提醒偏好。
4. 输入债券代码或名称关键词，点击 **查询基础资料**，选择结果；也可以直接填写完整 `securityId`。候选来自当前服务的 `ficc.base.query`，运行前通过 `ficc.base.get` 再次验证。
5. 点击 **开始 QA 功能测试（3条报价）**。测试会断开调试器原有连接，由独立子进程重新登录两个账号。结束后查看结果及 **打开报告**。继续手动调试前重新连接 GW。

不再限制为固定债券。当前 BaseSvr 适配器已加载的债券都可以选择，但本轮四类提醒测试要求该券具有 `RATE` 或 `CREDIT` 分类，且开始时没有有效行情；不满足条件时返回 `PRECONDITION_FAILED`，不创建报价。使用 QA 中无人同时操作的债券，避免外部行情变化干扰最优报价断言。每次只测试所选的一只债券，不遍历整个债券集合。

## 检查范围

| 范围 | 实际检查 |
|---|---|
| 登录与用户隔离 | 两个有效会话、不同 ownerUserId、第二个普通用户不能撤销第一个用户的报价 |
| 生命周期 | 新增待确认、确认、修改、撤销、恢复、删除；恢复保持 quoteId；七次历史连续 |
| 筛选查询 | 所选 securityId 条件命中新建报价 |
| 报价推送 | 私有报价通道收到匹配 quoteId 和最新 revision 的报告 |
| 行情推送 | 独立价格通道收到所选债券及对应 quoteRefs |
| 关注债券 | 临时关注分组命中后生成 WATCHLIST 提醒 |
| 筛选分组 | 临时条件分组命中后生成 FILTER_GROUP 提醒 |
| 对价提醒 | 两用户相反方向、不同结算方式的报价生成 COUNTER_QUOTE，并可标记已读 |
| 我的最优报价 | 生成 MY_BEST；他人更优报价使其失效；调整为同价最优后恢复 |
| 提醒推送 | 独立提醒通道收到 UPDATE 消息 |

总共创建三条报价：账号一买入收益率 2.5000，修改为 2.4900；账号二卖出 3.0000；账号二买入 2.4800，后调整为 2.4900。每条数量 1 万元，交易日取运行电脑当天日期。具有行权选项的债券使用行权收益率类型，其余使用到期收益率类型。该数据只用于功能验证。

本轮不验证界面点击或渲染、不测试压力、不遍历全市场，不覆盖 QT 接入或 CRM 匹配。报价不填写机构和联系人，不依赖尚未实现的 CRM 数据。

## 运行限制与清理

- 一个测试子进程，同机互斥，最多三条报价和两个临时分组；不自动增加压力。
- 工作阶段限时 60 秒，单项异步结果等待最多 6 秒；随后预留 20 秒清理。GUI 作为独立监护进程，在 90 秒时终止未退出的测试进程。
- **停止并清理** 发出停止标记，在当前调用返回后执行清理；关闭窗口时也先请求清理。
- 正常结束或可捕获的错误都会尝试撤销、删除本轮已知报价，删除本轮关注分组和筛选分组，恢复账号一原来的四个提醒开关。报价历史和通知审计记录保留。
- 偏好恢复使用测试保存时的 revision；若期间被其他操作修改，记录清理冲突，避免覆盖他人的新设置。
- 请求已发送但未收到回复时，创建或保存结果可能未知。报告保留 requestId、clientQuoteId、请求内容及偏好备份，提示人工核对。被强制终止时清理状态为 `UNKNOWN`，不能认为数据已全部清理。

## 报告与日志

每轮报告位于消息日志目录下的 `qa-日期时间/report.json`，通过 **打开报告** 查看。

| 字段 | 含义 |
|---|---|
| result | PASS、FAIL、PRECONDITION_FAILED、CANCELLED、CLEANUP_FAILED 或 ABORTED |
| steps | 已通过的业务断言及从开始累计的耗时；失败原因在 error |
| requests | 每个请求的 topic、requestId、第一/第二账号、内容、发送状态、回复 Code、往返耗时和是否属于清理 |
| reference | 本轮实际使用的基础资料 |
| createdQuotes | 本轮 quoteId 与 clientQuoteId |
| watchlist / filterGroup | 本轮创建的分组及 revision |
| preferenceBackup | 测试前提醒偏好，供恢复与异常核对 |
| cleanupErrors | 未能自动清理或提交结果未知的事项；不能忽略 |
| notCovered | 本轮未覆盖的功能范围 |

请求耗时是 C# 经 GW 到服务再返回的总耗时，不是服务间逐跳性能报告。完整业务收发消息写入共用 JSONL 日志，密码脱敏。两个密码仅从界面通过本机匿名管道传给子进程，不写入报告、命令行参数或配置文件。

## 构建与部署

源码入口：`client/src/QaFunctionalTest.cs`；GUI 入口：`api-debugger/src/ApiDebugQaTest.cs`。

在有 .NET 构建环境的电脑执行：

```powershell
dotnet build iteration1/api-debugger/DpsApiDebugger.csproj -m:1
```

远端没有 Visual Studio 时，可在本机构建后把更新的 `Ficc.DpsApiDebugger.exe` 放入远端现有调试器目录，保留同目录的 DLL、`.exe.config`、`requests.json` 和 `subscriptions.json`。本轮没有增加运行时 DLL 依赖。若首次部署，复制整个构建输出目录。需安装 .NET Framework 4.7.2 或兼容版本。

主 C# 客户端也包含同一个测试引擎入口，但推荐通过调试器 GUI 启动，以获得独立进程监护和停止清理按钮。
