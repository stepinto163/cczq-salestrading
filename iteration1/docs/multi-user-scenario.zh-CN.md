# 可重复的多用户报价场景

目标：用固定业务步骤验证两名用户的报价权限、实时视图及行情簿。不是并发压力测试，也不依赖随机行情或固定睡眠来猜测推送已到达。

## 固定数据

| 标签 | 用户 | 债券 | 方向 | 初始收益率 | 数量 |
|---|---|---|---|---|---|
| A1 | demo（U-001） | 250001.IB | 买入 | 2.5000% | 9876万 |
| A2 | demo（U-001） | 250002.IB | 买入 | 2.7000% | 9876万 |
| B1 | demo2（U-002） | 250001.IB | 买入 | 2.4000% | 9876万 |
| B2 | demo2（U-002） | 250001.IB | 卖出 | 2.6000% | 9876万 |

行情筛选限定上述两只债券、数量9876万，避免已有普通演示报价影响预期。“最优”在这个筛选结果内计算。开始前两个账户分别查询：若该范围已有有效、待确认或撤出报价，测试直接失败，不删除旧数据、不悄悄换一个测试范围。

每次运行重新生成requestId、clientQuoteId和quoteId；交易日期使用当天，时间戳由服务器产生。报告始终用A1/A2/B1/B2比较业务结果，实际ID保存在quoteIds映射中。

## 15个步骤

每一步完成后，两个订阅者都必须达到预期状态，才会进入下一步。

| 步骤 | 操作 | 关键预期 |
|---|---|---|
| 01 | 创建4条待确认报价 | 各自只在“我的报价”看到自己的2条；公共有效报价及行情为空；Bob不能读取Alice的待确认A1 |
| 02 | Alice确认A1 | 两人都看到A1行情；只有所有者能看到对手机构／联系人信息 |
| 03 | Bob确认B1、B2 | 买入顺序B1、A1；卖出B2；最优买入为B1 |
| 04 | Alice确认A2 | 出现两只债券，第一只债券的报价保持不变 |
| 05 | Alice尝试修改B1 | 返回1003，无状态、价格或revision变化 |
| 06 | Alice将A1改为2.4000% | A1、B1并列最优；同价时较新更新的A1排前 |
| 07 | Bob将B1改为2.3000% | B1重新成为唯一最优买入 |
| 08 | Bob用旧revision=2修改B1 | 返回1004；B1仍是2.3000%，版本不推进 |
| 09 | Bob撤出B1 | A1成为最优买入；B2和另一只债券不受影响 |
| 10 | Bob恢复B1 | 原quoteId恢复，版本推进，B1重新最优 |
| 11 | Alice撤出A2 | 第二只债券从行情消失；第一只债券完整保留 |
| 12 | Alice删除A2 | A2退出“我的报价”当前测试视图，后端状态为DELETED |
| 13 | Alice将A1数量改为9877万 | A1仍有效，但离开当前筛选范围；B1、B2继续显示 |
| 14 | Alice将A1数量改回9876万 | 同一A1重新进入两个用户的可见报价及行情 |
| 15 | 重发第14步相同requestId及内容 | 返回原结果，revision和历史记录不重复增加 |

每个用户建立四个独立视图：我的报价、可见有效报价、FULL行情、BEST行情。初始结果来自请求；后续视图状态仅由推送更新，不通过反复查询刷新视图来掩盖推送问题。测试检查序号连续性，以及两个用户的集合、价格顺序、收益率、方向、报价人、数量、引用报价版本和对手信息权限。另用quote.get核对实际状态、版本与价格，用history.query核对提交次数。

## 如何运行

后台服务启动后，打开最新原型：

```powershell
cd D:\workspace\greatewall\ficc\ficc
Start-Process .\iteration1\client\bin\MultiUser\Ficc.QuotePrototype.exe
```

点击顶部 **多用户场景**。不要求主窗口先连接，测试会建立自己的demo和demo2连接。过程显示在“自动测试”页，可点“停止测试”或“打开测试记录”。此场景独立于常规“自动测试”，不会自动叠加到原有8条报价的测试流程中。

也可执行：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\iteration1\scripts\test-multi-user.ps1
```

## 可预测性与结果

- 两个用户连接同时存在，但写操作严格按表中顺序执行，不使用并发写入或随机价格。
- 每步最多等4秒接收预期推送；不符合就停止。测试子进程最多30秒，脚本另有35秒监督上限。消息队列上限128。
- UI测试共用互斥锁，避免从多个窗口同时启动场景。请不要在运行时手动修改这4条测试报价，或向相同测试筛选范围加入报价；这种干扰会被判为失败。
- 完整报告包含steps[].expected、actual、result，以及quoteIds、cleanup、messageLogDirectory。每步及创建ID后都落盘；摘要步骤日志使用固定标签，DPS原始日志仍记录真实ID和完整收发消息。
- 正常结束或可捕获异常都会尝试撤出／删除本次创建的报价，并核对结果，不修改其他报价或个人偏好。强制结束、进程崩溃或断网可能留下记录；查看quoteIds及cleanup定位，下一次运行不会自动删除这些旧记录。
- 该场景验证报价和行情；四类通知规则仍由独立通知测试覆盖。

本次连续两轮均通过：每轮15步、293项断言、4条报价。两轮全部expected/actual步骤结果一致，测试报价均已删除。比较结果见 `runtime/multi-user-repeatability.json`；脚本报告保存在独立的 `runtime/multi-user-runs/<运行标识>/summary.json`，避免覆盖前一次结果。
