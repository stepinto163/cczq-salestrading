# STC UI 端到端测试管理

这是独立的测试管理窗口，业务界面复用正式 STC 客户端。测试连接真实 GW、LoginSvr、BaseSvr、CRM、ParserSvr、QuoteSvr、NotificationSvr 及其数据库；不使用模拟报价服务。

## 启动

与 `client.cmd` 同目录的本机入口：

```powershell
cd D:\workspace\greatewall\ficc\qa_env\ats_root\scripts
.\autotest.cmd start       # 打开测试管理窗口，不自动执行用例
.\autotest.cmd status      # 管理窗口及测试工作进程状态
.\autotest.cmd stop        # 请求停止、清理并关闭窗口
.\autotest.cmd restart     # 清理并关闭后重新打开
.\autotest.cmd build       # 构建测试程序；运行中会拒绝覆盖
.\autotest.cmd report      # 最近一轮报告路径、用例结果及清理状态
```

仓库内也有 `iteration1\scripts\autotest.cmd`，可从仓库根目录直接调用，参数相同。默认使用仓库同级 `qa_env\stc-client\STC.exe.config`，窗口会预填该配置；其他环境可传 `-StcConfig <完整路径>`。启动不自动构建或启动后端，用例在窗口中勾选执行。

重复启动跳过；只匹配本工程测试运行目录中的进程，不关闭日常 STC 客户端。停止最多等待 45 秒，让既有测试清理机制完成；超时保留进程并返回错误，不强制杀进程。命令行 `run-ui-tests.ps1` 已在执行时，`stop/restart` 会拒绝关闭，应等待其报告。`RUNNING` 仅表示进程存在，不能视为测试通过；核对报告的 `status` 与 `cleanupPassed`。

本机 `qa_env` 不随 Git 提交；可直接使用仓库入口，或仿照本机 `client.cmd` 创建同样指向 `manage-ui-tests.ps1` 的快捷入口。

先启动本机 STC/FICC 后端。从仓库根目录执行：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File iteration1/stc-client/stc-client/scripts/start-ui-tests.ps1 -Build
```

首次需要先构建 STC 客户端（`build-native-client.ps1`）。测试构建输出到 `runtime/ui-test-client`，不会覆盖正在运行的日常客户端。只启动已构建的测试管理窗口时，去掉 `-Build`。

选择环境的 `STC.exe.config`，默认账号/密码为 `test2/123456`，可修改账号、密码及债券代码。此版本要求 `Ficc.IntegrationMode=stc`，不把本机模拟模式的通过结果冒充真实服务验证。密码只传给本轮子进程，不写入用例文件。

所有用例统一用 `autotest.cmd start` 启动，不再区分普通/QT模式，不需要 `-QTrade`。真实 QT 发布用例24～26、41使用窗口里实际登录的 STC 用户作为收件人，通过 AdminSvr 用户目录读取该用户的 `stc_tbook_users.inf1`。没有映射、映射不唯一、用户目录不可用或发送人与收件人相同，都在发送前明确失败，不能退回默认收件账号。

| 参数 | 含义 |
| --- | --- |

### 1. 覆盖判定和执行次序

- P0：登录和页面可用 → 输入/选择/确认 → 正式行情及管理可见 → 修改/Refer/删除 → 提醒与清理。每次交付必跑相关路径。
- P1：多行/多方向、CRM歧义、字段边界、部分失败、分页和重复操作；按改动影响范围运行。
- P2：显示布局、复制/导出、键盘及演示；不会把正确性故障降级为P2。
- 每个功能检查正常、空输入、非法输入、边界、选择范围、重复提交、异步返回、跨页一致性、权限和失败恢复；不适用时写明理由。
- 「已有」表示有动作与断言；「部分」表示仅验证列明的子场景；「待补」表示没有可执行断言；「产品缺口」表示源码能力尚未完成。没有报告的用例不得记为通过。
- 真正的GUI证据应来自正式控件事件、显示内容及服务端独立读回；直接赋值ViewModel的旧动作只算绑定/服务集成覆盖，不能宣称完整鼠标/键盘覆盖。

## 隔离、断言与清理

每个用例启动独立的 STC 应用进程，使用独立的客户端状态目录，自动登录。业务写入通过正式界面的输入控件及按钮事件完成；测试不会直接调用 ViewModel 命令替代按钮，也不会直接改 `IsSelected` 来绕开 checkbox 绑定。

工作进程托管正式 `STC.App` 和同一套产品程序集，操作 WPF 控件的选中/点击事件。它验证 UI 绑定、业务处理、DPS 请求/推送及真实服务持久化；不是逐像素鼠标回放，对操作系统焦点、遮挡或拖拽的体验检查不在本轮覆盖范围。

服务端查询用于独立核对写入结果、历史以及清理，不代替业务操作。通知用例另通过 API 准备本例独立关注分组和偏好，保存原偏好到报告，结束删除分组并恢复偏好；报价创建/确认、通知标记已读仍通过正式 UI。数据库证据来自真实服务的持久化读取和历史 API，不额外直连 SQL 验证。

每例自己创建报价，自动记录 `owned-quotes.json`。结束或失败后，仅撤销/删除本例报价，并核对删除状态。软删除历史保留，不清空数据库，不删除其他用户数据；因此断言依据本例报价 ID，不依赖全市场固定总条数。服务拒绝或数据不符合预期即失败，不临时伪造预期。

套件有互斥锁，不允许多个实例同时运行。每个工作进程有独立超时监控；取消后最多等待 30 秒进行清理，超时只结束本套件启动的工作进程。若强制终止、进程崩溃或清理失败，报告标记清理未确认并停止后续用例，需检查本例 ID 和请求日志，不标记为通过。

## 浮动播放控制：速度、暂停与单步

管理器启动和开始运行时自动显示独立小浮窗，也可点击「播放控制…」打开。窗口可拖动、保持置顶、不阻塞业务窗口；点击右上角关闭只隐藏，可再次打开。停止并清理仍使用管理器中的独立按钮。

| 滑条位置 | 操作前等待 / 验证结果展示 |
| --- | --- |
| 0.25× | 8秒 |
| 0.5× | 4秒 |
| 1×（默认） | 2秒 |
| 2× | 1秒 |
| 4× | 0.5秒 |
| 最快 | 无额外等待 |

点击滑条会直接选择最近的速度刻度，也支持拖动及方向键。回归检查使用原生鼠标按下/移动/释放消息，在两种窗口宽度下核对六档速度，确认不会先跳到端点再回调中间速度；此前仅给 Value 属性赋值的测试不能发现这个问题。

速度变化约100ms内作用于当前人为等待，已等待时间不清零。暂停与速度分开：点击「暂停」阻止下一个控件动作或验证阶段，保留字幕与红框；已发送请求继续完成，行情推送继续接收，网络请求与页面查询超时保持原设置。显示“暂停请求”不代表中断了在途请求；工作进程到达等待点后显示“已暂停”。「继续」恢复所选速度。

暂停时，「下一动作」发放一个全局许可：只放行一个等待的客户端动作或一个验证阶段，之后仍保持暂停；双账号同时等待时由先领取许可的账号执行，不会各执行一次。它不是执行整个 JSON 复合步骤。验证阶段包含断言和结果展示，单步放行后不再为同一阶段要求第二次许可；结果留在当前页面，下一次输入仍需再次单步或继续。重复快速点击不会积累一长串待执行动作。

点击、文本输入（整次输入，不逐字）、下拉/页签/行选择、按键及编辑窗口操作都经过播放等待点。独立结果断言与双账号实时验证也有暂停点。须知自动处理、故障清理不等待人工继续；服务更新不会因播放暂停而冻结。显式 `filter.latency` 的控件操作仍跳过演示等待，不能把播放速度当成性能测量工具。

日志保留 `INTERVAL_WAIT` / `INTERVAL_DONE`（实际主动等待毫秒）、`UI_ACTION`，新增 `PLAYBACK_PAUSED` / `PLAYBACK_RELEASED`。每例目录的 `operation-interval-ms.txt` 保存速度对应间隔，`playback-control.txt` 保存共享暂停状态、单步许可与累计暂停时长。单步许可通过进程间文件锁领取。看门狗扣除显式操作等待及用户暂停时间；双账号阶段同步也扣除暂停时间。业务请求自身超时和停止后30秒清理宽限期不变。

## 演示字幕

### 当前操作与核对目标红框

自动化进程默认用 3 DIP 红色矩形标记当前目标。普通操作跟随输入、点击、选择及键盘焦点；进入验证阶段后锁定验证目标，其他控件获得焦点不会覆盖红框。不得用整个销售交易页面作为字段验证的默认目标。

| 验证内容 | 红框范围 |
| --- | --- |
| 识别的代码、方向、价格、数量、清算速度、交易日期、机构及交易员 | 指定报价行的对应单元格；多字段按顺序逐个验证 |
| 识别总条数、已选条数 | 底部条数标签、工具栏已选条数标签 |
| 识别警告、推荐字号 | 对应警告文本、标题、交易员文字或按钮 |
| 待确认、行情、管理或实时推送中目标报价存在 | 目标报价行 |
| 实时删除、私有报价隔离、结果不存在 | 当前页结果表格，并在字幕中标明报价标识和预期；不存在的行不能画框 |
| 页面就绪 | 当前页结果表格 |
| 服务端报价、持久化字段和历史记录 | 无界面红框，字幕标明服务端校验，结果保留在报告 JSON |

新增核对动作应使用 `await VerifyAsync(control, detail, assertion)`；报价字段使用 `await VerifyCellAsync(row, "清算速度", expected, () => row.Settlement)`。目标必须先定位、滚动并完成 WPF 加载，再展示红框、字幕及暂停点；随后执行断言和结果展示。多字段验证分别响应暂停、下一动作和速度设置，字幕包含债券、字段、预期值及实际值。

单元格通过目标行对象和列身份定位，不使用屏幕坐标或当前排序位置。滚动时保留行列虚拟化；找不到指定列、行或单元格，或目标隐藏、卸载、被回收时，明确报告验证目标错误，不静默退回整个页面。后台模型检查调用 `VerifyAsync(null, ...)` 清除旧框，不能借用上一次的控件充当验证证据。

红框使用 WPF 装饰层，不抢焦点、不遮挡鼠标、不改变布局，随控件缩放和布局移动，并按滚动视口裁剪。切换目标、控件隐藏或卸载、用例清理时移除旧框。正式客户端不启用此功能；未提供装饰层的原生窗口/弹出内容不绘制红框。正常步骤截图包含红框；`filter.latency` 动作暂停红框，避免干扰测量。

覆盖内容：

- Bid/Ofr 不同价格和数量；价格闭区间、等值上下界、数量下限边界；报价/全部页增加仅下限和仅上限。
- 价格 × 数量 × 清算 × 计价方式 × 搜索文本的 AND 组合。
- 清算 T+0/T+1 多选的同字段 OR；非远期展开和远期不命中。
- 计价方式是单选：净价排除收益率报价；切回收益率替换旧选择。不能把两个按钮当成可同时选中的条件。
- 搜索不存在文本、市场后缀大小写、空结果后恢复。
- 同时限定 Bid 和 Ofr 价格时，单条报价不能同时满足；清除矛盾条件后恢复。
- 不点清除过滤，只移除数量条件，确认保留的价格及清算条件仍生效；完整清除后旧条件不能残留。
- 利率最优按收益率 Bid 越小越优、Ofr 越大越优。各步骤预期别名显式写在用例中，不调用生产筛选器计算预期；价格和报量也必须与预期来源一致。

### 可编辑参数

`filter.prepare` 只准备六笔功能样本，参数为 `securityId`。`filter.combination` 通过真实控件操作，参数如下：

- `page/tab/view`：用例所属页面；目前支持 mgmt/today/MgmtTodayView、market/rateAll/BoardListView、market/rateBest/BoardBestView。
- `ranges`：JSON 对象文本，例如 `{"bidPrice":["6.1","6.4"],"bidQuantity":["300",""]}`。空字符串表示无边界；数量输入只有下限。
- `tags`：JSON 对象文本，例如 `{"quoteType":["收益率"],"settlType":["T+0","T+1"]}`。空数组用于取消该字段选择；空对象不修改已有枚举。
- `search`：搜索文本，支持 `${securityId}`；`<empty>` 表示清空。
- `expected`：命中别名，如 `B2,B3`；无命中写 `NONE`。最优页只填最优档来源，例如同组合报价页为 B2,B3，而最优页为 B2。
- `reset`：true 先点击清除过滤；false 保留未在本步骤指定的条件，用于验证增删条件。

执行时等待本次实际查询经历加载到完成，失败或超时不能当作零条结果。只比较本例六笔报价的集合，不把环境中其他报价算成错误，也不会清空其他人的数据。每步保存组合条件、查询 ID、预期/实际 ID 到 `*-combination.json`；别名与真实报价映射保存在 `filter-fixtures.json`。失败和正常结束均走既有归属跟踪清理。

### 本轮排除范围

本轮只用已接通且可通过正常报价流程控制的字段：bidPrice、offerPrice、bidQuantity、offerQuantity、settlType、quoteType、searchText。

- 不加入尚无可靠来源/业务口径的免税、地区等级、流动性等级、部分 Wind 标签等条件；不使用模拟值让这些用例通过。
- Bid–Ofr 盘口价差仍是禁用控件，跳过。
- 中债/中证估值、估值价差、评级、发行人等依赖外部资料快照的条件，本轮未覆盖；这不表示这些字段全部不可用。需另准备固定来源样本和日期、缺值期望后再加入，详见 `docs/product-filter-source-status.zh-CN.md`。
- 信用页、历史查询和报价旗标组合不在本组三页矩阵内，不能据此声称全产品筛选覆盖。

默认仍按 2 秒播放间隔逐操作等待，支持实时调速、暂停、单步和验证红框。该矩阵是功能回归，不测吞吐或延迟。
