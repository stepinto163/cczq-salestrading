# 原生销售交易接入进度

日期：2026-09-21。分支：`feature/ficc-native-salestrading`。

开发位置为当前仓库的 `STC.SalesTrading.Plugin`，已经加入 `STC.sln` 和本机编译脚本。复用 STC 登录、菜单、Tab、现有 `IApi` 连接；不启动独立客户端、不嵌入网页，也不加载 SZ 旧版本插件。SZ 仅作为参考。

## 本轮可用流程

| 产品区域 | 本轮接入 |
| --- | --- |
| 报价录入 | 分为“报价确认”和“精确报价”两个子页；待确认列表与批量草稿列表独立；手工录入、草稿预览／修改／移除、单条及批量保存；CRM机构／联系人搜索选择；急、荐、整、OCO、打包 |
| 报价管理 | 按产品HTML重排侧栏、今日报价／历史报价、Refer／Unrefer／删除／Copy／导出工具栏及23个业务列；当前列表仅显示本人有效／已撤销报价；双击进入编辑 |
| 行情中心 | 左侧条件筛选、中央行情、右侧报价明细；信用／利率、全部／最优切换；FULL按报价条目展示，BEST按债券显示Bid/Ofr；独立Price订阅 |
| 报价提醒 | 位于行情中心子页；独立Notification订阅、使用侧栏条件、列表及标记已读 |
| 产品筛选 | 布局由产品控件明确指定，不再把79个API字段全部生成表单；值来自服务字典。报价区使用五行双列范围、清算标签、收益率／净价；其余按债券／流动性／信用／条款／区域排列，提供期限预设及区域“更多” |
| 消息日志 | 底部可折叠辅助面板；REQ／REP／SUB／UNSUB／PUSH；默认隐藏HEARTBEAT，可勾选；可清空。窗口最多保存100条，完整消息同时写STC日志 |

报价管理最新状态按更新时间倒序、quoteId升序排列。用户滚动后进入浏览态，新记录不插入、不重排；“有N条更新，点击刷新”重新查询第一页。滚动边界使用view.query分批读取，每批30条，管理网格最多缓存300条，启用行列虚拟化；不是把全部报价载入网格。N是本视图推送中发生变化的不同报价ID数，不是全市场新增报价数。行情和提醒仍使用现有翻页交互，尚未移植滚动浏览态。

布局依据根目录 `FICC销售智能交易平台.html`。本轮实际用本机浏览器截取报价管理页面，与同尺寸WPF截图比较，调整384像素侧栏、标签、五行报价范围、工具栏和表格密度；保留STC宿主标题及导航，不嵌入网页。报价管理表格批量调用ficc.base.get补充债券显示资料，不逐行请求。精确报价和行情等其他区域仍待逐页对齐，不能认为整套产品UI已经验收。

界面“今日报价”沿用产品标题，但服务当前返回当前有效／已撤销状态集合，尚无交易日限定参数，不能声称已完成日切筛选。报价方式和长城交易员筛选因缺少对应服务参数暂时禁用；报价机构文本使用现有综合搜索，尚非机构专属条件。缺失的成交价／交易员名称等显示资料不伪造。

条件面板从字典返回值构造请求，中文名称仅用于显示。例如央企发送`YQ`；清算速度的远期／非远期转换为STC代码集合。录入的清算速度也来自同一字典，不再错误显示“明+0／明+1”。

报价确认列表和报价管理共用同一个报价topic，通过本地回调分发各自维护view；行情和提醒使用独立stream／topic／模型。初始化期间缓冲消息，按查询返回的sequence接续；缺号和连接变化后停止应用推送并提示重新查询。删除或退出条件造成第一页缺行时查询补位。

## 操作规则

1. 创建只保存 `PENDING_CONFIRM`，不会自动确认。
2. 确认仅用于待确认报价；修改支持待确认／有效报价；Refer仅用于有效报价；Unrefer仅用于已撤销报价。
3. 删除仅用于待确认或已撤销报价。有效报价须先Refer，按钮按状态启用。
4. 点击“读取／操作选中报价”或双击报价行，将完整报价及revision放入编辑区。实时列表更新不改写正在编辑的revision；冲突交给服务拒绝，用户重新读取后决定。
5. 输入机构／联系人名称可先保存待确认；确认时从CRM选择记录填入ID。修改名称会清除对应ID，避免提交旧关联。
6. 每批检查逐条结果；批量草稿移除成功项，保留失败项。网络超时后应先查询核实，不能认为报价一定没有创建。

## 验证与启动

沿用[本机联调说明](local-integration.zh-CN.md)的服务前提、编译和启动命令。真实GW连接本机QuoteSvr、NotificationSvr和PostgreSQL；固定登录及宿主启动依赖使用明确的本机模式。

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\build-native-client.ps1
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\test-local-integration.ps1 -NativeUi
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\test-local-integration.ps1 -SalesTrading
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\start-native-client.ps1 -Mode Local
```

`-SalesTrading` 驱动真实登录窗口和业务按钮，验证分类值使用STC代码、区间BETWEEN、期限LT、净价偏离字段映射、筛选／重置及信用FULL／全部债券BEST切换，并验证创建、确认、修改、Refer、Unrefer、删除、两条批量创建、历史读取、共享报价推送和独立行情推送。新增验证管理页排除待确认报价、浏览态保持顺序及恢复最新排序。测试只创建4条报价并清理本轮记录，保留服务审计历史；45秒看门狗保护，不执行压力测试，也未证明300条缓存边界的性能。结果在 `runtime/native-client/native-salestrading-result.txt`；启动检查生成确认、精确报价、行情及管理四页截图：`native-salestrading.png`、`native-precise.png`、`native-market.png`、`native-management.png`。

本机登录账号：`trader1`／`trader2`，密码均为 `trader1`。内网模式沿用真实登录配置；用户返回的prods包含`FICC`时将插件加入加载名单，菜单键25沿用旧销售交易插件编号。内网角色与菜单配置需QA验证，不能以本机成功代替。
