## 目标与范围

将 ParserSvr 依赖的自有解析能力重写为可维护、可测试的 Java 8 源码，最终识别链路不再依赖 `ParseLib.dll` / `libparser.so` 或闭源 Parsing 实现。最终运行目标为 Linux，本地 Windows 也应能运行纯 Java 实现。

这是一项完整替换任务，不是缓存优化、JNI 包装、初始化绕过或仅支持几个示例的简化解析器。重写范围包括原生解析逻辑，以及 Parsing JAR 中为替换原生依赖所必需的协调、转换和结果组装逻辑。**先盘点所有实际依赖能力及可达入口，避免只重写 `isCode` 或 `parseBond` 的一个分支。**

保留现有 STC 服务框架、GW/DPS 接口、BaseSvr/CRM 数据接入及 stc-client 产品交互。无须重写 STC、数据库驱动、标准库或整个销售交易平台，也不建立新的解析微服务。现有可复用 Java 实现保留，不为“全部重写”机械复制它们。

没有 C++ 原始源码；根据 Linux 符号、反汇编、Java 字节码、既有产品要求和行为样本重建实现。不能声称反汇编就是完整源码。Windows DLL 只作为补充参考；Windows 与 Linux 已存在行为／容器差异。

## 实现顺序：分阶段交付，最终覆盖完整能力

### A. 能力和合同清单

建立 `coverage.zh-CN.md`，每项列明入口、旧实现位置、输入输出、实现状态、测试 ID、证据和未知项。至少核查以下能力，实际依赖发现额外能力时加入，不能以此表作为删减功能的理由：

| 能力 | 核查范围 |
|---|---|
| 文本预处理 | 空白、标点、大小写、全半角、数字与单位、原文位置、换行及多行上下文 |
| 债券识别 | 代码、市场后缀、简称、别名、歧义候选、候选优先级、失效债券 |
| 报价字段 | Bid/Ofr、收益率／价格及类型、数量与单位、范围与多值、日期／清算速度、产品标志及缺省规则，以实际合同为准 |
| 多条与上下文 | 一段文本多个报价、表头继承、机构／交易员上下文、报价所属原文和顺序 |
| 机构／交易员 | 文本提取与 CRM 解析边界、同名歧义、关联机构、缺失或无法识别时的结果；不另造 CRM 数据库逻辑 |
| 字典生命周期 | 初次加载、重复、改名、删除、有效性变化、start/end、刷新及失败时旧快照处理 |
| 其它可达功能 | 枚举 Java 包装层公开方法与 JNI 入口，说明哪些是服务实际使用、哪些兼容入口须保留；无法确认的不能静默删除 |
| 外部合同 | 请求、响应、错误码、缺省／空值、数字精度、列表顺序、识别失败／部分成功及配置开关 |

状态使用 `NOT_STARTED / IMPLEMENTED / VERIFIED / BLOCKED / OUT_OF_SCOPE`。`OUT_OF_SCOPE` 必须有“不属于当前依赖功能”的证据；未知规则写明具体输入和疑问交回，不自行发明。

### B. 先建立可执行测试，再逐模块实现

不要只交付设计文档。完成盘点后，从字典和债券识别开始，继续完成字段解析、多行上下文、结果组装及服务适配。每个阶段都应可编译、有测试，并更新覆盖清单。

- 使用明确 Java 类型表达请求、债券候选、报价结果、诊断信息；JSON 只在现有服务边界转换。
- 解析核心接收字典快照、业务日期和配置，不在解析方法或静态初始化里连库、读机器环境或隐式启动线程。
- 数据获取沿用现有 BaseSvr/CRM 接口，测试使用小型固定数据；时间／时区显式传入，以便重现。
- 字典构建完后一次发布不可变快照；解析中读到一致版本。刷新失败保留旧快照并清楚记录失败，首次加载失败不能假装就绪。
- 代码索引、名称候选及有效性集合职责明确；候选顺序必须稳定。避免每个 token 扫描完整债券库，避免用并发掩盖平方级算法。
- 保留现有入口的兼容适配，提供可审阅的 ParserSvr 集成补丁。旧实现仅作为测试对照和切换前回退，不得在 Java 模式漏功能时偷偷调用 native。
- 参数不支持、数据缺失和错误必须有明确表现，不以空结果／硬编码数据冒充成功。
- 按现有规范输出初始化状态和失败栈；解析日志包括请求关联、字典版本、结果数量及诊断，不能把内部异常吞掉。

### C. 验证行为，区分“测试通过”与“兼容已验证”

**用户补充：以当前可工作的二进制为基准，对测试集中的每一个输入做旧／新实现对照。这是主要验收机制，必须实现可复用比较运行器，不只手工选几个成功示例。**

比较流程：`固定输入与环境 → 旧实现原始结果 + Java 实现原始结果 → 逐字段差异 → 用例状态与报告`。

- 每个测试输入两边完全相同，包括文本、字典内容和版本、业务日期／时区、配置及 CRM 查询返回；不能让两边各查实时数据库后把数据变化误判成解析差异。机构／交易员场景还要对齐服务层后处理，不能拿纯 native 输出直接比较最终 DPS 响应。
- 基准二进制记录 OS、架构、SHA-256、配套 JAR 哈希。当前可运行 Windows 二进制可建立 Windows 对照集，但 Linux 生产替换仍须独立 Linux 基准；两套结果不能混为一份预期。
- 旧版原始输出、候选原始输出和差异都保留。差异定位到字段路径及列表下标，包含缺失／多余报价、值、类型、空值、顺序、错误／部分识别及超时。不只比较报价数量或是否成功。
- 每个输入必须有状态：`MATCH / DIFF / BASELINE_ERROR / CANDIDATE_ERROR / TIMEOUT / NOT_RUN`。两边都报错不自动算正确，要核对该用例预期和错误合同。
- 增加或修改解析规则后重跑整个固定对照集。发现新业务输入时保存为用例，并尽可能记录原始二进制输出，后续可离线回放。预期结果带基准版本，禁止为了测试变绿直接用新实现输出覆盖基准。
- 同一个输入可首次由旧实现生成基准，后续用已保存基准做快速回归；字典／配置或旧库版本变化时显式更新基准版本。原生每次都启动全量加载并不是“每输入比较”的必要条件。
- 比较器是测试工具，不直接接入真实下单或确认报价流程，不导致两次创建报价。每输入对照覆盖已收集测试输入，并不等于已证明任意未知文本都等价。
- 可提供单用例与整套命令，例如 `compare --case <id>`、`compare --suite <file>`，实际命令由实现确定。报告实时显示已执行／总数及各状态，失败用例可单独重放。

建立可按 ID 单独运行、可按能力分组运行的固定输入／预期结果测试集。每个用例标明预期来源：Linux 旧实现实际结果、已有产品合同、已核验业务样本或待确认推断。纯推断样本不能作为兼容完成的依据。

- 覆盖正常、边界、错误和歧义；尤其是多行、多报价、同名债券、失效代码、缺字段、刷新后改名／删除、CRM 多候选。
- 对照比较完整业务字段、候选及结果顺序、单位、空值和错误；仅对已明确无业务意义的差异做归一化。
- 不因旧实现可能有缺陷就自行改变兼容目标。把“已知旧行为”“建议新行为”分别列出，交回决定。
- 无法运行 Linux 旧库时，允许推进有证据的实现和纯 Java 测试，但 Linux 对照标 `NOT_RUN`，不能宣称完整等价。
- Java 单元测试应小数据、顺序执行，配置外部进程超时、单测试进程及有界堆；超时后停止并报告，不自动增加资源或重试。
- 本任务不授权启动全量旧解析器、真实库初始化、原生探针、共享服务／客户端或压力测试。真实性能验证单独提出短时、最小负载方案，用户确认后才运行。

### D. 完整替换验收

全部能力实现后提供纯 Java 模式集成产物、Maven 构建命令和 Linux 验证步骤，交 Codex 审查后再部署。

最终验收必须证明：

1. Java 8 可编译打包，明确实际测试的 JDK／依赖版本及未完成平台验证。
2. 解析路径不再加载 DLL/SO，也不转调旧 Parsing 实现；在不提供这些库的测试环境仍可工作。
3. 覆盖清单没有被隐藏的未实现／阻塞项；每项有对应测试。不能把一个最小子集称为完整替换。
4. Linux 对照与现有 DPS 接口集成测试完成，机构／交易员、多个报价及 stc-client 识别确认流程保持业务合同。未获运行授权或环境缺失时保留 `NOT_RUN`，先交候选而非宣称已发布。
5. 初始化和解析性能有另外授权的实测结果；不使用 Windows 历史耗时宣称 Linux 提速，也不凭算法分析承诺延迟。
