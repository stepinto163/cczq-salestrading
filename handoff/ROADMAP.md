# 协作路线图

这是候选顺序，不是自动执行队列。只有 INDEX 中 ready 的 task.json 可执行。每项完成并经 Codex 评审后再派下一项。

| 阶段 | WorkBuddy 的小任务 | Codex 的职责 | 完成依据 |
|---|---|---|---|
| 0. 交接试运行 | 只读审计三个文档入口的本地链接 | 验证分支、格式和证据 | 报告可复核，无越界改动 |
| 1. 测试管理窗口 | 先验证新增/编辑/复制/删除及重启后保存，再另派小修复 | 确认需求，评审及独立 UI 复测 | 用例可管理，失败明确，既有用例不被破坏 |
| 2. 核心回归 | 每次补一个场景：生命周期、识别确认、CRM、历史、筛选、价格推送 | 定义预期和业务边界 | 可重复运行、数据独立、清理可核验 |
| 3. 通知回归 | 按四种通知逐个补例，明确账号/行情条件 | 校验产品规则及触发逻辑 | 触发、不触发、用户隔离 |
| 4. 多用户 | 按给定操作顺序实现两用户场景，不先随机并发 | 设计确定性时序、权限及冲突期望 | 可复现，不依赖前例残留数据 |
| 5. 可维护性 | 局部日志、确定边界内的类型化模型、重复代码整理 | 审核 API/框架兼容，拆分跨模块改动 | 行为不变，有相关回归 |

性能测试单独立项，需要用户明确授权、进程超时保护和小负载起步，不混入普通功能任务。需要协议/数据库迁移、公共框架修改或环境重装时停止扩展，交回设计讨论。
