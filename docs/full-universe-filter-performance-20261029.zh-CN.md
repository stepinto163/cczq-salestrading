# 全量有效券筛选与实时更新：首档 5 客户端

## 结论

实际运行 **89,526 只有效券、每券 1 条报价、5 个并发客户端**。结果 **FAILED**：完成四轮、核对 20 次接收端推送后，第五次修改请求超过 30 秒未收到应答。没有继续运行 10/20 客户端。

全量筛选/新视图构造在 QuoteService 共享锁内完成，导致其他查询和写入排队；已完成请求最大锁等待 **22.98 秒**。之前优化的当前页选择约 0.06–0.11 ms，已不是本轮主要耗时。

## 数据及测试边界

- 从真实本机 FiccBaseSvr 导出一致版本的 112,346 条参考；保留 RATE/CREDIT 且 `maturityDate >= 2026-10-29` 的 89,526 条：RATE 44,002、CREDIT 45,524。排除已过到期日的 22,820 条；同步快照已排除删除记录。
- 每券一条 ACTIVE Bid 收益率报价，价格 2.00、数量 1,000 万；按债券行权属性选择收益率口径，不触发 CalSvr。直接造数到随机 schema，不覆盖识别/确认生命周期。
- 缺少 DM 属性的券仍保留。评级非空 56,587，地区非空 83,512。全部、评级 AA+、地区 320000、两者结合且价格 ≤2.02，初始分别命中 89,526、2,299、6,774、239 券。目标报价改为 2.09 后组合命中 238，恢复后为 239。
- 使用固定的真实 FiccBaseSvr 导出属性及生产 DM loader；DM 源表只读。计时期间不进行真实参考同步。五个独立 GW 会话复用两个模拟身份，不是五个不同业务用户；不测真实 LoginSvr。
- 链路：WebSocket → 标准 GW → DPS → QuoteResource → 客户端解码。不是 WPF 绘制时延。
- 每客户端一个常驻 FULL 逐笔视图，条件为全部、评级、地区、组合、全部；每页 50 行。每轮五客户端并发 query、打开同条件临时视图后关闭，最多十个视图；第一客户端同时修改报价。计划五轮、轮间 200 ms，闭环等待，不是固定 QPS 或最大吞吐测试。

## 资源、失败及清理

- 本机约 32 GB RAM；各测试进程限制两逻辑 CPU、低于正常优先级。QuoteSvr 堆上限 3 GB、GW 256 MB、ZooKeeper 128 MB、Node old-space 512 MB。数据量与当前渲染/加载页行数分开统计。
- Python 父进程独立 watchdog 每 250 ms 采样；可用内存低于 3 GB 或整栈超过 360 秒即终止自有进程，客户端整体预算 180 秒。
- 正式失败运行：自有进程峰值 RSS **3,638.40 MB**、系统最低可用内存 **8,582.72 MB**，未触发内存保护。RSS 不含共享 PostgreSQL，系统可用内存包含其影响；未采集完整 CPU/GC 时间序列。
- 第一次尝试使用 90 秒客户端整体预算，被 watchdog 中止；保持相同数据/并发重跑，增加每秒结果检查点并延长整体预算。第二次因真正的 30 秒单请求超时结束，含启动约 195.69 秒。
- 参考导出准备时全量 JSON 物化超过导出进程 1 GB 堆；改为每页 1,000 条流式写出后成功。这是导出工具问题，不属于业务并发结果。
- 两次测试均确认自有进程退出、报价 schema 删除、测试端口无残留；未修改 DM 原表、用户原报价或常驻服务。
