- ParserSvr原先将“明+1/明+0”提取成“+1/+0”，丢失明日含义；现在与“明天+1/明天+0”同义，也支持“明天加一/明加零”。

## 给前端的简单示例

接口：ficc.quote.accurate.identify。2026-11-19识别下列文本：

```text
bid 240210.IB 2.9155 2000 明+1
```

响应Data.Datas每行新增tradeDate：

```json
{"securityId":"240210.IB","tradeDate":"2026-11-20","settlType":"4"}
```

识别接口旧编码保持不变：1=今天T+0，2=今天T+1，3=明天T+0，4=明天T+1；它不是正式报价接口的清算编码。既有MM.dd日期编码亦保留。前端后续可优先使用tradeDate显示交易日；本地同事客户端尚不读取新字段，已通过原有3/4编码显示正确日期与速度。
