# 筛选候选复用与网关回包分段诊断（2026-10-29）

## 666 ms 到底花在哪里

上一轮 `20261029-224818-full-5` 的筛选中位样本为无约束广泛视图，实际 666.176 ms。关联 requestId `FULL-2d482107-7694-4e01-850a-d26b3837872b`：状态捕获 3.991 ms、临时索引 46.010 ms、匹配分组 128.001 ms、候选准备及排序 479.353 ms，其中候选准备 345.992 ms，50 行 JSON 物化仅 0.048 ms。锁等待约 0，QuoteSvr 总计 658.460 ms。

它并不是只排序返回的 50 行：全部 89,526 条报价参与成员维护；每券一笔时，券内价格排序简单，但仍重复解析价格/时间、分配对象并组织 89,526 个债券组。这里没有证据将某次 GC 精确归因于该 666 ms 样本。

## 分段诊断

- QuoteSvr 性能日志增加开始/结束墙钟时间，保留纳秒单调时钟耗时；测试客户端记录对应墙钟边界。
- 增加可选 `--trace-gateway`，只对隔离测试 GW 加载 Java agent。记录原有回包接收、入队、出队、INFO 日志、send 调用起止，内容仅测试 requestId 和时间；不改 GW jar、转发逻辑或日志策略，同时记录 GC 暂停。
- `summarize_gateway_timing.py` 按 requestId 汇总，缺少必要阶段直接报错。本轮前后均完整关联 60 个测量请求。
- 同机墙钟只有毫秒精度；网关 send 返回不等于网络已送达；队列阶段包含探针、调度和 GC。跨进程区间不能精确拆成网络时间，探针本身有开销。

诊断基线 `20261029-230704-full-5`：首笔修改端到端 365 ms，QuoteSvr 内约 120 ms，GW 接收至出队约 187 ms。时间重合的 GW 年轻代＋Full GC 共暂停约 185 ms，其中 Full GC 167 ms；该笔日志约 0.18 ms，send 调用约 0.64 ms。因此该例不能归咎于打印完整日志。QuoteSvr 另在首次打开期间 Full GC 约 1.33 秒，在后续阶段出现约 1.67 秒应用暂停；旧 1.46 秒异常没有这些探针，不能倒推其全部原因。

## 本次优化

1. 共享只读排序候选缓存：按报价对象身份、参考版本、收益率口径与换算结果校验；报价更新失效，版本或换算变化替换。目标容量 100,000 项，超过目标不继续新增。沿用展示缓存的并发容量检查，非严格内存字节上限。
2. 每次请求仍执行权限和筛选检查，缓存不保存用户可见性或过滤结果，避免跨用户泄漏。
3. FULL 构建直接使用已捕获分组，不再预建完整临时报价索引；若期间有更新/换算需要追赶，再在锁外准备索引后执行原追赶流程，保证同券其他报价不会丢失。
4. FULL 不再生成仅旧式价格簿路径使用的 latest 时间字典；单券分组列表初始容量从默认 10 改为 1，降低每券一笔场景的无用数组分配。多笔仍正常扩容。

本次没有提高堆、CPU 或超时，没有更换 GC，没有改变外部协议、部署配置和业务排序规则。
