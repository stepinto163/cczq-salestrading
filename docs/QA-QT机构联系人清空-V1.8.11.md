# V1.8.11 QT自动识别未匹配字段清空

前序已发V1.8.10为测试套件；产品代码基线仍V1.8.9后端`9bb65e4a`。本次只修改QuoteSvr的QtCounterpartyResolver及测试，补Python真实接口回归；无Common/Base/Notification/QtIntake/Parser产品修改、无配置或DB迁移、无前端源码。包含此前未交付的本轮所有相关改动，前序依赖与未验项不撤销。

用户明确本次仅做清空/展示规则，**不加入相似度评分，不改变精确优先/唯一包含/分页唯一性判断**。

| 自动识别结果 | 机构 | 联系人 |
|---|---|---|
| 机构无匹配或多义 | ID与名称空 | 未显式选择的ID与名称空 |
| 机构匹配、联系人未匹配或多义 | CRM ID及简称；简称空用全称 | ID及名称空 |
| 均匹配 | CRM ID及简称 | CRM联系人ID及名称 |

已经显式传入的ID不删除、不重选，继续由QuoteService按CRM权限/所属关系校验并填规范名称；单独传联系人ID但无有效机构时，保留该ID交由原校验拒绝，不静默改成无对手报价。非文本错误输入仍报原校验错误，不通过清空把无效请求洗成有效。

CRM查询异常继续抛错；先在副本完成匹配，再回写，避免联系人查询失败时部分更新机构。日志`QT_CRM_RESOLVE`保留原机构/联系人名称与最终匹配ID，来源text保留；原始QT名字不再当作已确认CRM字段展示。群路由、去重键、输入哈希计算顺序均不改。相同negotiationId更新旧待确认报价时，显式null也会清掉旧匹配值。

影响：没有匹配到CRM的QT草稿现在四字段为空，因此不再因未匹配的名称触发UNRESOLVED_COUNTERPARTY；现有系统允许无对手报价，用户仍可选择CRM。已有历史/存量草稿不批量修复，只对新接入及待确认协商刷新生效。
