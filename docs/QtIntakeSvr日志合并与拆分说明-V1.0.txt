QtIntakeSvr 日志合并与拆分说明（V1.0）

只改配置，不需要改 Java 代码。当前没有单独的“合并/拆分”开关。
关键配置：logger 后面的 file / dpsMessages 决定写入哪个文件；Threshold 决定接收哪些日志级别。

配置位置
服务目录：$ATS_ROOT/stc/QtIntakeSvr/control/QtIntakeSvr/log4j.ini
仓库：iteration1/cgws-ficc-saletrading-qtintakesvr/control/QtIntakeSvr/log4j.ini
部署副本：iteration1/cgws-ficc-saletrading-qtintakesvr/salt-formula/cgws-ficc-saletrading-qtintakesvr/files/control/QtIntakeSvr/log4j.ini

一、合并到一个文件
替换以下现有配置项，不要在文件末尾重复追加同名项：

log4j.appender.file.Threshold=DEBUG
log4j.logger.ficc.common.client.NetClientTransport=DEBUG,stdout,file
log4j.logger.ficc.common.client.StcBaseSvrClientBridge=DEBUG,stdout,file
log4j.logger.ficc.common.client.PostgresCrmClient=DEBUG,stdout,file
log4j.logger.ficc.qtintake.messages=DEBUG,file

结果：应用日志和DPS/FIX消息都写入
$ATS_ROOT/log/QtIntakeSvr_YYYYMMDD.log

二、恢复分开记录（当前默认）
替换为：

log4j.appender.file.Threshold=INFO
log4j.appender.dpsMessages.Threshold=DEBUG
log4j.logger.ficc.common.client.NetClientTransport=DEBUG,stdout,file,dpsMessages
log4j.logger.ficc.common.client.StcBaseSvrClientBridge=DEBUG,stdout,file,dpsMessages
log4j.logger.ficc.common.client.PostgresCrmClient=DEBUG,stdout,file,dpsMessages
log4j.logger.ficc.qtintake.messages=DEBUG,dpsMessages

结果：
应用日志：$ATS_ROOT/log/QtIntakeSvr_YYYYMMDD.log
DPS/FIX日志：$ATS_ROOT/log/QtIntakeSvr-dps_YYYYMMDD.log
分开模式下，通信INFO摘要可能出现在两个文件；DEBUG正文只进入DPS文件。

三、两种模式均保持以下设置

log4j.rootLogger=INFO,stdout,file
log4j.additivity.ficc.common.client.NetClientTransport=false
log4j.additivity.ficc.common.client.StcBaseSvrClientBridge=false
log4j.additivity.ficc.common.client.PostgresCrmClient=false
log4j.additivity.ficc.qtintake.messages=false
log4j.appender.file.File=../../log/QtIntakeSvr
log4j.appender.dpsMessages.File=../../log/QtIntakeSvr-dps

其余输出器定义、日期滚动设置保持原样。不要让两个不同输出器写同一个文件。
主题正文长度上限、心跳开关仍按payload-log.properties生效；独立startup启动日志保持不变。
发布时同步上述仓库配置及Salt部署副本，由Jenkins部署，重启服务后核对日志输出。
本说明仅说明配置方法，本次没有修改运行配置或切换服务日志模式。
