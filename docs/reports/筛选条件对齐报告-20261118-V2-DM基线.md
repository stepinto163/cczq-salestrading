# 筛选条件对齐报告 V2 以DM供给为产品边界

2026年11月18日。本文替代V1的整改方向；V1保留作原型与现行代码的事实比对，不删除历史结论。

**本轮的目标是让需求和前端适应可提供的数据，而不是要求后端实现原型中每一个选项。** 但“当前代码没映射”不等于“DM没有数据”。发行年份、含权标志、地区等已有来源，仍应修接线或表达方式；报价价格、报量、归属和日期属于业务数据，也不因DM约束而取消。

本报告提供产品与开发的调整建议，尚未修改原型、客户端、后端或部署。所有逐项建议见[81字段完整CSV](筛选条件对齐矩阵-20261118-V2-DM基线.csv)；该矩阵同时列出原需求、当前客户端/后端、供给依据、建议产品要求及两端工作。

## 1. 数据证据与结论强度

- 沿用V1基线：客户端`colleague_20261029/stc-client` HEAD `9e9e41ac4`，本机收到的同事来源`31b53bb08`；后端`.tmp/qa-source-mail-20261117/backend` HEAD `57aa27b0`。完整路径、版本及哈希见[V1报告](筛选条件四层对齐报告-20261118.md)和[证据索引](筛选条件对齐核查-20261118-证据索引.json)。本轮重新校验20份源码哈希，未变化。
- 当前能证明的是**源列、装配方式、默认映射及请求处理链**。本轮未取得新的QA枚举分布或完整供应商宽表字典，不能把某个选项永久删除的依据写成“已证实DM不存在”。
- “暂不开放”是以当前已接通能力界定本期支持范围的建议，不是判定供应商永久缺数据，也不是本轮已实施的UI变更。若其他DM表已有所需数据，应改判为接入工作。
- 一个选项今天没有命中券，不等于该选项不受支持。候选应依据明确的数据契约和映射，不应随当天样本是否为零任意消失。
- DM可以包含宽表之外的辅助表；可核准的派生规则也能支撑需求，但必须与供应商原生字段区别说明，不自行发明分类。

前端不能仅删除XAML里的标签：大部分候选会在启动时被服务端字典重新替换。若采纳本期范围，服务端可用选项、前端目录和原型必须一起对齐；保留公共API，不因本期隐藏而删除协议字段。缺失、未知和“其他”必须分开。

20项热门标签的来源逐项表沿用[V1第5节](筛选条件四层对齐报告-20261118.md#5-20个热门标签逐项核对)。V2处置是“16项保留并验收、4项当前不承诺且查供给”，不是要求直接扩展四个未经证实的映射。

## 4. 数据已存在，不应靠缩减需求解决

| 条件 | 供给证据 | 正确整改方向 |
|---|---|---|
| 发行年份 | `bond_iss_year` | 保留任意年区间；修客户端IN与Core数值执行器不支持IN的断点；并补区间入口 |
| 可赎回/可回售 | `embedded_option`、`put_option_status`、`redeem_status` | 四个正反选择并非DM无法支持。可赎回对应CAL/CNP，可回售对应PUT/CNP；交叉组合需先求交集，不能平铺成同字段OR。反向选择需确认缺值语义 |
| 省/市/区县 | `com_basic`、`area_info`及宽表区县码 | 修地区控件字段绑定，接真正地区目录；地区评级与地理地区分开 |
| 发行人/担保人 | 发行人简称、担保人全称已有源列 | 联想候选与过滤值一致；全称选中却只搜索简称的问题应修接线 |
| 地方债地区/重点省 | 已有省份和名单派生 | 补合并提醒/管理面板入口；明确地方债当前仅省级、重点省名单依据 |
| 四类永续 | 已有永续/城投/金融属性派生 | 核准规则后让信用页与合并页能力一致；不能因信用页只有是/否就说DM不支持四类 |
| NCD | 当前源码明确有NCD分类 | 明确信用页面市场范围；不能用固定CREDIT排除部分NCD后删掉NCD需求 |
| 剩余期限 | 稳定到期日可供计算 | 保留按日计算；不要求DM每天另供一个期限数值，不改回陈旧年限 |

**对V1的重要更正：**“分类不同”只证明接口表达不同，不自动等于应改需求。例如含权四个正反条件可由已有标志支撑；发行人类型则是系统派生，不能直接当作DM标准。共享库修改仍需遵守用户之前约定，保留公共接口和缺失值契约。

1. 产品确认第2、3节的本期范围和名称：尤其行业、资金类型、提前还本、临时不开放候选。当前是提案，没有擅改原型。
