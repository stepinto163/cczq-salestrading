# QA合并说明：20261119-R4 流动性分档配置修复

接续20261119-R3。本次提交为 `d5f71c68`，基线为 `519592cc`。

## 修改原因

客户端按S/A/B/C/D档位筛选，DM提供liquidity_score数值。现有BondSearch Core已有评分转档位逻辑，但服务没有配置分档规则，加载后的liquidityGrade为空，档位筛选因而查不到数据。

## 合并范围

仅修改以下四个配置文件，每份增加同样的规则和中文注释：

- cgws-ficc-saletrading-quotesvr/config/adapters.properties
- cgws-ficc-saletrading-quotesvr/salt-formula/cgws-ficc-saletrading-quotesvr/files/config/adapters.properties
- cgws-ficc-saletrading-notificationsvr/config/adapters.properties
- cgws-ficc-saletrading-notificationsvr/salt-formula/cgws-ficc-saletrading-notificationsvr/files/config/adapters.properties

包中sources是两个组件的完整源码，patches是各组件仅包含本次配置变化的补丁。请优先合并这四处配置；若QA有其他独立修改，不要用完整源码覆盖它们。本次不修改Java业务代码、Common、BondSearch Core、BaseSvr、ParserSvr、客户端或接口，不增加数据库迁移。

## 最终规则

```properties
liquidity.grade.bands=S:90:100,A:70:90,B:50:70,C:25:50,D:0:25
```

Core按配置顺序取第一个命中档位，必须保持S、A、B、C、D的顺序。相邻闭区间共用端点，实际效果如下：

| 档位 | 实际范围 |
|---|---|
| S | 90≤评分≤100 |
| A | 70≤评分<90 |
| B | 50≤评分<70 |
| C | 25≤评分<50 |
| D | 0≤评分<25 |

89.5归A，90归S；69.5归B，70归A。缺失值和超出0～100的值不归档，不按0分处理。原始评分不舍入。按已确认五档口径，E对应低分并入D。
