## 精确报价、新报价直接提交及价量空值

- 原因：原提交先 create 再 confirm，确认失败会留下待确认报价。用户讨论后明确批准在 create 增加 confirmOnCreate，由服务端逐条原子创建正式报价，返回确认校验错误；不改变机构、价量非必填规则。
- 改动：GatewayQuoteService.SubmitQuotesAsync 发送 confirmOnCreate=true，核对成功回执 status=ACTIVE，不再为新建行另发 confirm；保留部分成功回执、未知通信结果的原 requestId 重试，以及已有待确认记录的确认能力。错误或不符合约定的回执不伪装成成功。
- 空值问题：QuoteEntryDialog.BuildQuoteRow 原本忽略 TryParse 的成功标志，空价格/报量变成0，触发报量必须大于0校验；并非服务端把价量改成必填。现在空输入保留 null，显式零值不当成空值；窗口报量提示与服务校验一致。该转换来源于 b54f08c571，之前整合验证漏查了此入口。
- 仓库/分支：colleague_20261029/stc-client，dev_sales_trading_backend；对应服务端在主仓库 integration/ficc-client-convergence 的 Common 和 QuoteSvr。需配套发布；旧服务端不支持新参数时明确报错，不退回两步提交。
- 实际验证：tests/run-colleague-regression.ps1 在独立 .tmp/direct-submit-client-build 构建目录执行完成，450条 PASS 输出；包括服务模拟回执的原子提交、部分失败重试、超时幂等、拒绝待确认回执，以及真实WPF新报价窗口四种价量组合与显式零价格/空报量转换。外层进程带3分钟终止保护。
- 限制：这是客户端组件/模拟网关回归，不是登录真实服务后的桌面端到端或QA验收。本次未替换正在使用的客户端DLL。后端真实PostgreSQL事务验证记录见主项目 docs/task-memos/2026-11-02.md。
