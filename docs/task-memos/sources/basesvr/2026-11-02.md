## FICC全量快照分页优化

- 原因：用户批准启动优化方案三。此前每取一页都扫描整个固定快照，109296条、每页1000条需要约1202万次条件检查，属于重复工作造成的性能问题。
- 改动：BondReferenceSnapshot在发布版本时建立只读有效行列表与总数；全量页按偏移取行，解析仅本页记录。保留原排序、固定版本、增量水位及删除标记；无变化增量直接返回空集。增量有变化时仍遍历原快照，不改接口和业务。
- 验证：Java8构建及19项JUnit通过，新增覆盖多页、固定旧版本、删除、增量、空末页及大偏移边界；新增分页测试采用固定页数避免异常时无限循环。曾用系统Java17构建失败（旧注解处理器不兼容），切回项目Java8后成功。本机BaseSvr已替换备份后的主JAR并启动，QuoteSvr和NotificationSvr均下载109296条成功。
- 边界：未单独测出分页优化的毫秒收益；整个组合优化还包括Common复制路径、服务并行初始化及JVM设置，不能把全部收益归给本项。现有公共接口和同事BondSearch Core未因本项更改。
- 来源：feature/ficc-reference-data；主项目汇总D:/workspace/greatewall/ficc/ficc/docs/task-memos/2026-11-02.md。未推送GitLab、未重新发QA包，QA尚未验收。


## 增加剩余期限展示字段

- 用户要求：在remainingYears之外提供180D、3.3Y及行权分段期限，复用BaseSvr现有逻辑。
- 实现：BondReferencePolicy.bondRow保留原BondInfoView.TimeToMaturity；FiccReference新增remainingTerm直接映射该值。原STC在CommonDataManager内用Utils.calcTenor生成该文本；不另写计算算法，不在持有资料读锁或每次分页时重算11万条日期。
- 语义：普通券为D/Y；待行权为距行权日 + 行权至到期；永续沿用 + N。保留原STC小数精度，可能为3.30Y。源值缺失返回空，更新时效沿用原STC资料更新流程；remainingYears及其估值口径不变。
- 验证：Java8 package成功，全部20项JUnit通过；新增用例使用原Utils.calcTenor生成180D、行权Y + 180D、永续 + N并核对透传、缺失和数值年限不受影响。无性能压测、未部署或重启当前服务、未修改客户端显示。
- 分支：feature/ficc-reference-data；Common契约与中文说明在主项目integration/ficc-client-convergence同步。产品代码仅本地提交，未推送或发QA包。
