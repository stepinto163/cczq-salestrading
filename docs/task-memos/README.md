# 工作记录约定

这里保存用户与开发助手的可追溯工作记录，补充 Git 差异中的“为什么这样改”，不依赖某次聊天能否完整保留。统一入口为 [INDEX.md](INDEX.md)。

## 每次改动怎么记

沿用 `YYYY-MM-DD.md`，同日追加，不为每个小任务新建 memo。每项简短记录：

- 目的：原行为、实际问题，以及用户确认的目标。
- 改动：最终采取的处理，涉及仓库、分支、提交或可定位的源码路径。
- 验证：实际执行的检查、结果和证据位置；代码检查、本机服务、桌面、QA 分开说明。
- 状态：完成、进行中、待验证或已回退，以及剩余工作。

代码、配置、文档和环境操作都要记录；只读调查有重要结论或决策时也记录，不能把调查写成已修复。后续推翻旧结论时追加更正，不掩盖历史。提交号可在后续索引中补充，避免为引用自身提交反复改写历史。

## 跨仓库与交付核对

每个源码仓库的原始 memo 是事实来源，本索引登记所在位置。`sources/colleague-client/` 是同事客户端备忘的归档副本，保留原文；更新时从已核对的源码版本同步，不在副本上修改业务结论。

交付前按日期范围检查所有相关 memo、提交差异和最终代码。逐项判断是最终保留、被后续修改替代、已回滚、只读调查，还是仅本机环境操作。用户要求对外清单删去的内容，仍保留内部记录。测试只报告实际覆盖，不把组件断言数量当作桌面用例数量。

## GitHub 工作档案

- 仓库：`https://github.com/stepinto163/cczq-salestrading`。
- 文档分支：`codex/work-records`；入口：`docs/task-memos/INDEX.md`。
- 此分支仅归档工作记录、交付说明和记录规则，不作为产品构建或合并基线。
- 先在各源码仓库保存、验证并提交记录，再把核对过的文档复制到该归档分支；保留已有档案，以普通提交和非强制推送追加更新。
- 若分支已有远端更新，先获取并合并文档变化，不覆盖他人的提交。推送后核对远端提交号；失败时明确说明“本地已保存，远端未同步”。
- 每次记录新增或更正后，在用户已授权的范围内同步档案；不得为了同步文档直接推送开发分支中无关或未获准发布的代码。
- 只存必要的事实、决策与证据索引，不保存密码、授权码、完整聊天或原始业务日志。其他项目先在自己的仓库记录；跨项目汇总登记入口和范围，不自动复制整个源码仓库。

## 使用边界

本机全局 `C:/Users/loong/.codex/AGENTS.md` 保存通用记录习惯；仓库 `AGENTS.md` 保存项目规则。更换机器或工具时需要配置相应规则读取入口，不能把文件存在等同于任何聊天都会自动读取。当前会话也不会在无人运行时持续自动同步。
