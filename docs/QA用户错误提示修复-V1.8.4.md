# 用户错误提示修复 V1.8.4

日期：2026-11-26。前序交付：V1.8.3。性质：后端源码候选；真实接口回归通过，客户端页面尚未验收。

## 用户确认的要求

- 弹窗只说明业务问题，不出现任何内部ID、错误码、协议字段、gateway前缀或异常栈。
- 不追加“请从下拉列表重新选择”“请重试”等操作建议。
- 可用第几条、债券名称、机构名称定位失败项；没有名称时不拿内部ID代替。
- 前端仍由同事维护。本包不包含客户端源码或补丁，请前端同事按下文同步修改。

## 后端修改

| 组件 | 修改 | 兼容性 |
|---|---|---|
| Common | ApiResponse统一生成中文业务提示；移除原先拼接的ID、字段值、版本号；固定错误目录和已知动态错误统一转换 | Code、requestId、error结构及诊断字段保留，调用方仍可按错误码处理 |
| QuoteSvr | 批量失败附可读名称与条目序号；历史失败回执重放刷新旧文案；登录及推送重置提示统一 | 不改变报价状态、幂等结果或数据库结构 |
| NotificationSvr | 分组变化、连接重置的直接推送提示统一 | 提醒协议和筛选行为不变 |

示例：`第1条，华林证券：报价交易员未匹配成功`。
机构未识别：`第1条，未匹配测试机构：报价机构未匹配成功`。
不存在的报价：`第1条：报价不存在`。
结构化诊断仍保留供程序和日志使用，不能把整个error对象展示给用户。本次没有修改DPS/FIX原值记录策略。

旧幂等失败回执在读取时刷新提示，无需迁移数据库；已成功回执和失败操作的业务结果不变。未知异常不直接展示下游原文，使用对应中文业务错误。
