前端对接：剩余期限展示字段 remainingTerm

1. 从已有基础资料同步接口取值，不新增接口。
服务：SERVER.BaseSvr；接口：ficc.reference.sync。
返回片段（省略其他字段和分页信息，数值仅为示例）：
{
  "Datas": [{
    "Bond_ID": "示例券.IB",
    "FiccReference": {
      "securityId": "示例券.IB",
      "remainingYears": "3.7956",
      "remainingTerm": "3.30Y + 180D"
    }
  }]
}

2. 两个字段分工不同。
- remainingTerm：可空字符串，只用于展示，直接显示服务端原文，例如180D、3.30Y、3.30Y + 180D。
- 行权示例中的两段分别为距行权日、行权日至到期日；永续券可能为3.30Y + N。
- remainingYears：保留原值，用于原有数值筛选和排序。不要用remainingTerm替换它，也不要从展示文本反推年限。

3. 前端接法。
基础资料DTO、缓存字段白名单和持久化均保留remainingTerm，页面按券代码从本地缓存读取；不要新增逐条base.get。
同事客户端的候选列表示例：
  entry.Tenor = string.IsNullOrWhiteSpace(record.RemainingTerm)
      ? record.RemainingYears : record.RemainingTerm;
字段缺失时沿用原显示逻辑，不猜测行权分段。

4. 注意旧缓存。
旧缓存可能已经保存最新版本号，却没有这个新字段。升级后需补拉一次完整快照（新一轮同步ReferenceVersion为空，后续仍沿用原分页流程）；即使服务端版本号没变，也要保存补齐字段的新快照。
成功后恢复增量同步，失败保留原缓存，不必每次启动全量下载。

当前演示仅接入“关注债券管理”的右侧候选列表，其他页面无需跟着修改。先升级配套BaseSvr，再升级客户端；旧服务没有该字段时仍按原逻辑显示。
