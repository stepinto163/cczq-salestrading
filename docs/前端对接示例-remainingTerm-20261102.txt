前端对接：剩余期限本地计算（2026-11-02增量更正）

1. 沿用基础资料同步与本地缓存，不新增接口。
SERVER.BaseSvr / ficc.reference.sync 返回的稳定字段示例：
{
  "Datas": [{
    "Bond_ID": "示例券.IB",
    "Maturity_Date": "20300502",
    "Option_Date": 20291103,
    "Option_Type": "PUT",
    "FiccReference": { "securityId": "示例券.IB", "remainingYears": "3.7956" }
  }]
}

2. 日期留在本地，由客户端原STC算法计算。
STCHelper.SetShowTenor(SimpleBondsInfoPo) 使用 DateTimeEx.ServerTime。
例如当前日期为2026-11-03，上述日期显示3Y + 180D。
普通券显示180D或3.30Y；行权券为距行权日 + 行权日至到期日；ETS沿用 + N。

3. 同事客户端演示写法（只改关注债券管理右侧候选列表）：
entry.Tenor = FiccBondReferenceCache.CalculateRemainingTerm(record.SecurityId)
    ?? record.RemainingYears;
该函数只读本地日期并调用原算法，不发base.get。无日期时回退原年限；日期已过期或格式无效显示--。
打开页面重新识别时按当天计算；窗口持续打开时每30秒检查服务器日期，跨日重算候选行，关闭时停止检查。

4. 保持兼容，不回滚接口。
remainingTerm字段、DTO、缓存列和旧缓存一次升级机制保留。
服务端remainingTerm/TimeToMaturity仅代表快照形成时的兼容文本，不能当作每日最新值；它们单独变化不增加同步版本。
到期日、行权日、条款、估值等实际数据变更仍产生增量。
remainingYears数值筛选/排序口径不变。本地计算无需每日全量下载，也无需等待新增文本字段补齐。

本说明替代此前“直接显示服务端remainingTerm”的接法。已发V1.0包不会自动更新，须合入本次增量修复。
