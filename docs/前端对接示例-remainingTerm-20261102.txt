1. 基础资料同步只使用稳定日期，不再下发remainingTerm和remainingYears。

    "Option_Date": 20291103,
    "Option_Type": "PUT",
    "FiccReference": { "securityId": "示例券.IB", "maturityDate": "2030-05-02" }
  }]
}

2. 展示：复用原STC算法，只读客户端缓存，不调用base.get。
entry.Tenor = FiccBondReferenceCache.CalculateRemainingTerm(record.SecurityId);
当前日为2026-11-03时，上述示例显示3Y + 180D。
普通券为180D、3.30Y等；行权券为距行权日 + 行权日至到期日；ETS沿用 + N。
缺缓存、缺日期、无效日期/条款显示--并记WARN；异常记ERROR及堆栈。正常已到期显示--。
不返回null，不回退估值年限。本次只接关注券候选列表，其他页面没有批量接入。

3. 数值：本地ToReferenceJson/Find返回的remainingYears也是由当前日、到期日计算。
整年加不足一年天数/目标年份天数，保持筛选精度，不用展示文字反向解析。
缺少有效到期日返回null，已到期为0；不读取估值的remaining_year。
该计算值不写入基础资料SQLite，也不作为同步更新条件。
客户端使用DateTimeEx.ServerTime；服务端筛选使用上海业务日期，并在跨日失效计算缓存。

4. 同步：请求结构不变，继续保存ReferenceVersion，成功完成全部分页才提交检查点。
BaseSvr持久保存同步标记；重启后只返回实际变化及删除。
旧的内存版本迁移到持久化版本时会补一次全量，此后重启或跨日不强制全量。
真实日期、估值、评级、债券库等内容变化仍会产生增量。

5. 行情中心“我的报价”：信用/利率全部和最优均下推ownerScope=MINE。
取消勾选恢复默认可见范围；翻页、导出使用同一归属条件。
这是列表筛选，不是权限开关，也不改变报价归属。
