# 历史报价排序修复与自动迁移（2026-11-17）

- 修复：历史报价原按首次操作时间升序，现按界面的报价时间从新到旧；时间相同按历史日期倒序、报价ID升序，空时间在最后。分页和导出同序，筛选含义不变。
- 部署组件：本次增量仅QuoteSvr。无需修改客户端协议或增加配置；以当前Common/此前历史资料快照版本为基线编译。
- 数据库：QuoteSvr启动自动将history.daily.version升级为5。在现有quote_history_daily增加quote_time timestamptz，从snapshot.quoteTime回填，并更新维护触发器和既有券/日期覆盖索引。不会修改原报价时间、历史快照内容或将空时间替换为撤销时间。
- 升级前备份，维护窗口统一更新QuoteSvr实例。首次启动有回填、索引重建及短期表锁；以实际数据量安排，不能套用本机247ms。失败事务全部回滚并拒绝就绪；后续正常启动不重复回填。旧程序不识别版本5，回退需配套数据库方案，不能只改版本标记。
- 兼容范围：沿用PG10式复合索引，不使用INCLUDE、数据修改CTE或新增数组绑定；QA的TBase实机升级及执行计划仍待核验。没有执行百万报价或并发压测。

核对SQL（先使用服务配置里的schema，不要直接假定public）：

```sql
SELECT value FROM metadata WHERE key='history.daily.version'; -- 5
SELECT count(*) AS inconsistent
FROM quote_history_daily
WHERE quote_time IS DISTINCT FROM NULLIF(btrim(snapshot->>'quoteTime'),'')::timestamptz; -- 0
SELECT pg_get_indexdef('history_daily_formal_security_idx'::regclass);
-- 券、日期仍为前缀：(security_id, operation_date, quote_time, quote_id)
```

验收：创建不同时间报价、修改早期报价、按不同顺序撤销；历史按最后报价时间倒排。分别检查无筛选、有筛选、跨页、同时间、缺失时间及Excel导出，不能只在客户端当前页重新排序。本机原错误三笔已验证为14:04:13→14:03:35→14:03:34。
