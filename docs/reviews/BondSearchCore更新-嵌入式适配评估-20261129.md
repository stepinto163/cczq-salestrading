## 2. 保持的边界

现有报价过滤主链是`QuoteSvr/NotificationSvr → ReferenceData/BondScopeFiltering → BondSearchHost.matchBondScope(Filter) → BondSearchEngine.matchIds(Filter)`。这是同一进程的Java方法调用。两服务分别托管DM快照和索引；Core返回券代码集合，报价、权限、归属、关注列表、分组及提醒规则仍由业务服务处理。

同事`BondSearchService`已有网络请求包装、session解析配合和`QuoteSvr hitset`回调。它为独立服务形态提供能力，但不应成为FICC内嵌筛选的新必经路径。否则会出现本地筛选绕网络回调QuoteSvr，增加延迟、失败依赖及重复业务处理。

建议保留同事原topic/API兼容层，不删除公共接口；FICC直接复用Core算法，通过宿主Java方法对接。对客户端确需提供的新能力仍由既有FICC服务入口鉴权并映射响应，不新增独立BondSearchSvr。topic命名如已有统一契约可沿用，架构是否一致取决于调用路径和责任边界，而非topic名字。

## 3. 按业务能力采纳

| 能力及目的 | 建议接法 | 边界 |
|---|---|---|
| 命中券ID集：供下游按券集合筛选 | 继续使用现有`matchBondScope`，必要时增加有限券代码范围重载 | 不把报价筛选改成调用无分页`ficc.bondsearch.ids`；不向前端每次发送完整券宇宙 |
| 地区树：省市区导航、计数和下钻 | Core保留行政区划装载与树聚合；QuoteSvr准备范围后本地调用，返回树 | 计数单位是债券，不是报价；若范围为用户可见报价，先按报价权限生成券代码集，再聚合 |
| 同业地方债：同发行人，或同地区档/期限档/一般专项 | Core负责纯债券规则和目标自身排除；FICC把返回券集与现有报价条件、权限求交 | 不是全券种通用相似算法，不替换现有收益率排序、推荐规则或报价去重 |
| 地区分类、期限档 | 采用可配置派生实现，字典/合法值由Common一致注册 | 这些是业务认定规则，不是DM原始事实；待确认默认规则不能静默当作批准需求 |
| 发行人全称 | 复用DM全称装载与专门的issuerName匹配，保留简称支持的明确约定 | 该改动不自动修复所有搜索入口；新代码的综合searchText仍只拼券码、券简称及发行人简称 |

建议宿主提供的能力是“匹配券集”“在指定券集上聚合地区树”“查相似地方债券集”，具体方法名实施时按既有API风格确定。跨业务/Core边界传稳定券代码，不传跨快照ordinal位图；位图只在固定快照内部转换和使用。

## 4. 需要先处理的源码和兼容问题

### 4.1 区域骨架依赖数据库返回顺序：已做局部复现

`OnshoreFilterTableLoader.loadRegionSkeleton()`对市/区一次查询、没有排序，然后逐行调用Builder；`RegionSkeleton.Builder.district()`在市节点不存在时直接跳过。

用附件原版`RegionSkeleton.java`编译一个三节点探针，未改源码：省→市→区得到1个区；省→区→市得到0个区。证明Builder存在顺序依赖，数据库当前是否恰好返回有序行未实测。优先改为先收集再分级构建，不依赖SQL自然顺序。还要覆盖重复行政码、缺父级及直辖市特殊层级。

证据：[局部探针结果](../test-results/bondsearch-review-probes-20261129.json)。这不是DM数据库或服务端到端验收。

### 4.2 新地区树与当前Common的直辖市编码不一致

新树为北京构造`field=city, code=110000`节点；本机Common `FilterDictionaries.canonical()`只直通不以0000结尾的6位city码，现有城市字典为北京110100，因此city=110000被拒绝。必须核对QA配套Common及真实DM行值，再统一树节点、下钻条件、行属性与旧保存条件的兼容；不能只改树标签或对所有省码放开city验证。新测试验证了合成节点外观，但未覆盖北京合成市节点向当前Common下钻的跨版本链路。

### 4.3 一次请求内必须固定同一DM快照

`BondSearchEngine.matchIds()`先从current取位图，遍历时又反复调用current.row；并发刷新可把旧ordinal映射到新券或越界。此问题在本机旧实现已经存在，不归责于本次新引入。

新similar链路先算位图，再取得报价scope，之后再次读取当前快照分页；regionTree结果与watermark也分别读取快照。适配时须从范围转换、匹配、计数、排序到watermark/游标签发共用一份快照，不能只在单个底层函数加局部变量就认为整个组合请求一致。跨页保持现有水位变更拒绝旧游标的契约，不增加长期保留历史快照机制。以上为源码分析，未执行并发复现。

### 4.4 Common依赖与共享API不完整

当前Common缺`BondSearchSimilarRequest`、`BondSearchRegionTreeRequest/Data`、`BondSearchIdsRequest/Data`以及termBucket和新topic契约。Core快照本身引用这些类型，即使FICC不调用对应网络topic，也不能忽略编译依赖。需获取配套Common版本，逐项合并必要增量，不整体覆盖我们已有修复。

`OnshoreRowAssembler`从旧8参数构造改为11参数、没有保留旧重载，属于公共签名不兼容。应恢复兼容重载/工厂，在支持新能力同时保留同事原有调用方。POM同为0.1.1-SNAPSHOT不能证明实际类契约一致。

### 4.5 业务规则、日期口径和初始化依赖

- 地区分档配置包含“好/中/弱/差”名单；期限分档注释明确25年以下待业务确认，兵团启发式也待确认。30年同时落在两个声明区间，但当前按顺序取首项而归25–30年档；应显式核验边界及配置顺序，不擅自改变业务结果。
- 新termBucket由DM剩余天数/365生成。本方`BondScopeFiltering`特意不把remainingYears交给DM，而按当前日计算。新分档不能悄然取代原剩余期限筛选；需先确认是否同基准日，覆盖跨日临界样本。
- 新版无条件增加com_info_out全称和area_info名称/父级查询；SQL失败会使初始化失败，不能因未调用新topic就宣称无启动影响。核对真实表、列、权限与目录加载耗时。不得静默用空目录伪装初始化成功，也不得引入STC/sample数据兜底。
- 普通issuerName与综合searchText的全称/简称支持应分开验收，不能因专门字段改全称就宣称全局文本搜索全部修复。

## 5. 性能约束

保留现有内存索引和有上限的条件缓存、快照刷新失效；新增能力按需计算，不在每笔报价到达时重建地区树。地区骨架每次DM快照构建一次，计数按实际筛选范围求值。includeEmpty会增加树节点数量，但不应返回完整债券对象；报价列表仍分页及增量。Notification只接它实际需要的匹配能力，不为了与QuoteSvr组件对齐额外执行树聚合。

不增加Core到QuoteSvr的网络自回调；内部较大的券集合可用于集合运算，但不自动暴露给客户端。新增缓存如确有必要须有容量和快照失效边界，不引入无上限历史快照持有。当前无性能实测，任何压测仍需用户另行授权。
