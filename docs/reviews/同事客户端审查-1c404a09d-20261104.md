## 需要处理的问题

### 1. P1：旧的补齐缓存覆盖刚收到的资料增量，并推进版本

位置：`Shared/Reference/ReferenceSyncService.cs:243–263`；缓存恢复另见 `:148–153`。

当某券当天已经通过 `base.get` 补齐并落入 enrichment 表后，后续 `reference.sync` 即使返回该券的新评级、估值或行权日，代码仍然用当天的旧 enrichment **整行替换新资料**：

```csharp
if (changed.ContainsKey(pair.Key))
{
    pair.Value.FromSnapshot = false;
    changed[pair.Key] = pair.Value;
}
ReferenceCache.Publish(changed.Values, deleted, full, pinned);
```

例如上午缓存评级 AA，下午同步收到 AA+，最终发布及保存的仍是 AA，但资料版本已经前进。下一轮服务端可正常返回“无变化”，因此不是简单等五分钟就一定能恢复。行权日及估值同样受影响。

同一缓存策略还有删除边界：删除只从 reference 表移除，未清理 enrichment；当日重启时 RestoreFromDisk 又无条件把 enrichment 加回字典，可能复活已经删除的券。

建议：新版本的明确字段和删除信息优先；补齐缓存只补真正缺失的字段，并依据版本失效，不能仅凭“当天缓存”覆盖新快照。

### 2. P2：行权报价在全部行情及报价管理的悬浮提示中被当作到期报价

位置：`Gateway/GatewayModelMapper.cs:126–133`；`Shared/Components/QuotePriceHover.cs:183–203`；`Modules/QuoteMgmt/View/MgmtTodayView.xaml:146`。历史报价和全部行情也直接绑定 `QuoteType`。

协议用 `quoteType=1` 表示收益率，另以 `yieldType=2` 表示行权。映射后 `QuoteType` 是 `YieldToMaturity`，`YieldType` 才是 `ToExercise`，但悬浮组件只收到前者，没有接收收益率口径。

因此一笔行权收益率报价会显示“到期收益率”；有 maturityYield 时显示的是另一个口径，无 maturityYield 时又把原始行权价格当作到期收益率回退。组件虽然接收了 exerciseYield，也不会进入行权分支。

建议：传入组合后的有效计价类型，或让提示组件显式接收 YieldType。最优页使用单独的价格簿类型映射，不能据本问题推断最优页也必然错误。

### 3. P2：查询失败时，查询期间已经收到的实时推送被清空

位置：`Gateway/MarketQuoteLiveView.cs:226–236`；`Gateway/ViewSnapshotBuffer.cs:33–55`。报价视图查询同样调用该缓冲类。

发生顺序：已有页面数据 → 发起刷新并开始缓存推送 → 收到一条有效更新 → 刷新请求超时/失败 → catch 调用 Reset(epoch)，直接清空 pending。这个失败路径没有把已收更新应用到旧快照，也没有在此处作废视图并补拉。

因此在实时流仍健康、只有刷新请求失败的情况下，本地会遗漏已收的一次更新，直到以后另一次快照或涉及同条报价的推送才可能修正。

实际使用附件中的原始 `ViewSnapshotBuffer` 编译小探针（仅替代消息 DTO，不连接服务），结果：

```text
successReplay=1; failureBuffered=True; failureRetained=0
```

这证明组件确实清掉了已缓存更新；并非桌面断网端到端复现。建议失败后明确恢复一致性：保留并安全处理该批推送，或把视图置为待重新同步，不能清掉后继续把旧快照当最新。

### 4. P2：报价管理初次回填剩余期限仍依赖 remainingYears

位置：`Gateway/GatewayReferenceFill.cs:431–436`；`Gateway/GatewayModelMapper.cs:63`。对比同文件 `ApplyTape` 的 `:88` 与刷新路径 `:275`。

行情行初次回填调用 `BondTerm.Calculate(rec)`，但 QuoteRow 的初次回填仍直接取 `rec.RemainingYears`。通过 base.get 补齐得到的记录也会直接写缓存，没有先走 ReferenceCache.Publish 的期限计算。

当服务端提供 maturityDate / optionDate / optionType、但不再提供 remainingYears 时，首次打开今日/历史报价可能显示空期限；若仍提供数值 remainingYears，则可能显示裸数值，而行情显示格式化期限。后续 ReferenceCache.Changed 才会调用正确的计算，且无变化的同步不触发该事件，不能依赖它及时修复初始展示。

建议：QuoteRow 初次回填与刷新统一使用已有 BondTerm.Calculate。该发现是新期限功能接入不完整，不能据此声称所有报价管理查询都必现空白。
