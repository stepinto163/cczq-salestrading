# BaseSvr 债券规模字段

| FICC字段 | DM来源 | 单位 |
|---|---|---|
| initialIssueAmount | bond_basic.initial_issue_amount | 万元 |
| totalIssueAmount | bond_basic.total_issue_amount | 万元 |
| remainAmount | bond_amount.remain_amount | 万元 |

三个字段为可选十进制字符串，放在 `ficc.reference.sync` 每行的 `FiccReference` 内；QuoteSvr 的 `ficc.base.get`（kind=SECURITY）和现有资料查询直接保留。现有接口和referenceSchemaVersion保持兼容。前端负责新增字段映射和展示，未修改客户端源码。

```json
{
  "securityId": "019702.SH",
  "initialIssueAmount": "2300000.000000",
  "totalIssueAmount": "13800000.000000",
  "remainAmount": "13800000.000000"
}
```

以上为本机真实服务样本。需要显示亿元时由展示层除以10000，协议保持万元。缺失不补零、不补STC；实际零余额仍返回零。

关联：现有DM宽表经bond_code_convert取得combination_code，再关联bond_basic和bond_amount。基础表取非删除最新update_time/id；存量表取非删除、change_date不晚于上海当天的最新change_date/id。未来和缺少生效日期的存量记录不用于当前余额。规模变化参与现有ReferenceVersion增量计算。

用户提供的LEFT JOIN LATERAL语法及关联正确；本机bond_amount仅有id主键，原LIMIT 100查询触发5秒超时，未进行压力测试。实现先批量归并再关联，不新增数据库索引。原SQL还会取未来生效余额，本机已有2030年生效的零余额记录。

42项BaseSvr测试通过（含真实PostgreSQL隔离schema边界测试）；实际DM→BaseSvr→真实网关→QuoteSvr前端接口三个样本原值一致。前端缓存/页面尚未接入验证，QA/TBase未验证；不能标记完整桌面端到端验收通过。
