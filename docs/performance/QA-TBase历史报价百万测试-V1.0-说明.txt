QA TBase历史报价百万测试 V1.0
日期：2026-11-03

目的
验证当前TBase兼容版历史查询的数据库性能。之前百万级性能数字来自修改索引前的本机PG16，不能直接当作本版QA结果。

测试内容
1. 在独立schema ficc_history_perf_probe建表，生成100万个不同报价ID、10万个不同债券ID，分布于28个日期。
2. 建立当前兼容版的5个查询索引（不使用INCLUDE），执行ANALYZE。
3. 测试100个券ID、1万个券ID、10万个券ID的第一页，以及10万个券ID的第1500页；每页50条，每种3次。
4. 每次实际返回总数和报价JSON，校验总数与行数。输出每轮耗时、最小/中位/最大耗时、执行计划与缓冲区统计。
5. 最后ROLLBACK，清理表、索引、函数和schema；remaining_schema应为null。

如何运行
使用QA测试数据库的现有连接信息，建议通过psql一次运行整个SQL文件，保存输出：
psql -X -v ON_ERROR_STOP=1 -h 数据库地址 -p 端口 -U 用户 -d 测试数据库 -f "QA-TBase历史报价百万测试-V1.0.sql" > history-perf.txt 2>&1
上面的中文参数替换为QA既有连接信息；密码交互输入，不放进命令或结果文件。
也可用数据库工具的“执行脚本”，必须全程同一连接，并保存每个SELECT的结果。不要只执行选中片段。

运行边界
- 只在获准的QA测试库执行，单连接串行，不要同时启动多份。需要CREATE SCHEMA权限，建议至少3GB可用磁盘。
- 不读取或修改业务schema。若同名测试schema已存在，CREATE SCHEMA会直接失败，不覆盖、不删除它。
- 建表/造数/索引单条语句上限180秒；查询单条上限8秒。TIMEOUT就是失败，不计为成功耗时。
- 不进行VACUUM、不调大work_mem、不修改服务配置。刚造数并扫描验证后的首轮不是磁盘冷缓存。
- SQL全程未提交。异常或取消后，在同一连接执行ROLLBACK，或关闭该连接；不要手动COMMIT。
- 3次样本不足以报告可靠P95；本脚本不输出P95。

请回传
整个history-perf.txt。重点看数据库版本、daily_rows=1000000、distinct_quotes=1000000、distinct_bonds=100000、4组耗时、执行计划、failed_queries_or_plans=0和remaining_schema=null。
同时说明QA数据库是否有其他负载、机器CPU/内存和数据库部署方式，方便解释结果。

测量范围
这是每日历史查询表的合成数据测试，不包含审计回填、触发器同步、DM筛选耗时、并发用户、网络、Java服务和桌面加载。券ID数组模拟DM返回的匹配集合；不是验证DM业务匹配结果。
本机只用1000条数据检查脚本语法、结果和回滚清理，未运行本版百万级负载，也未代替QA TBase执行。
