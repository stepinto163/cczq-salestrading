二、新增更新
1. 数据库断连恢复：原持久连接被数据库关闭后会一直失败。现在重新连接、恢复会话与单写锁，并重载业务内存状态后恢复服务；提交结果不确定时不盲目重复写入。
2. 内部同步内存修复：原恢复重试可能保留多份全量快照。现在限制内部同步快照生命周期、按页编码、及时释放游标和快照，避免重试持续累积；保持分页期间的数据一致性。
3. 提醒恢复重试：报价源切换后放弃旧同步轮次，不把旧游标继续带到新连接；恢复失败采用2/4/8/16/30秒退避，并补充诊断日志。
4. 最优行情三价：Common/QuoteSvr保留计算器返回的到期/行权收益率、净价、全价；为需要展示的最优档补算，保留原报价值。客户端信用最优、利率最优及同档报价浮层显示三类价格，缺失显示--；不再按默认清算条件在浮层自行重算。排序、报价状态及原输入不变。
5. 回归材料：补充独立数据库故障、跨实例游标、通知恢复、三价映射及客户端浮层检查；附真实计算服务六组验证摘要。附带此前单独邮件发送的QA百万报价SQL脚本及说明，内容未再修改。
6. 日终截止改为00:00（Asia/Shanghai）：源码默认、源码运行配置和Salt默认参数统一更新。11月3日的正式报价在11月4日00:00日终撤销；零点停机时，下次启动补处理昨日及更早的有效报价，不误撤当天报价。截止时间仍可配置。

三、包内容和合并
sources/为四组件目标源码快照，供参考或全量对照；客户端沿用V1.2源码清单，未变的宿主运行二进制依赖不重复附带。不要覆盖QA已有修改。
patches/为各组件本次增量；changed-files/为改动文件方便阅读，manifest.json记录精确提交、文件列表和应用路径。
在Common、QuoteSvr、NotificationSvr各自源码根目录执行：
  git apply --check -p3 <对应补丁绝对路径>
核对后再用git apply -p3；客户端在同事客户端源码根目录使用-p1。
有本地修改或基线不一致时人工合并冲突，不强制覆盖。补丁和完整源码是两种合并辅助方式，不需要重复应用。
support/包含已有回归入口及辅助脚本；validation/为实际验证摘要；docs/为本说明及QA百万测试脚本。
file-sha256.json校验包内文件，ZIP旁附.sha256校验整个包。
只从已提交Git版本导出，不包含客户端工作区其他未提交修改、运行日志、临时兼容JAR或数据库转储。

四、构建和部署
先构建安装Common，再按原Jenkins/Salt流程重建QuoteSvr、NotificationSvr；客户端按现有VS构建流程重建插件及依赖。
沿用$ATS_ROOT/control共享配置。本次无新数据库表、迁移版本、服务接口或必填配置；既有quote.endOfDay.cutoff默认改为00:00。Jenkins/Salt环境参数如已显式覆盖quoteEndOfDayCutoff=22:00，需同步更新为00:00，通过流水线渲染；核对最终service.properties及QUOTE_END_OF_DAY启动日志。重启QuoteSvr后生效，此次打包不直接修改QA运行服务。此前V1.4.1历史迁移版本3及BaseSvr估值分离前提仍需保留。
备份后部署配套Common、两服务及客户端，按原服务启动方式运行，确认数据库恢复/报价源同步READY。不能把仅进程存在视为初始化成功。

1. 合并后mvn package；运行已有历史回归，确认原筛选、总数、分页、迁移仍正常。
2. Windows先将support/iteration1/scripts中的脚本合并到现有工程的iteration1/scripts（其相邻目录为三个服务源码和runtime），再运行iteration1/scripts/test-storage-recovery.ps1 -Configuration <现有测试配置绝对路径>。不要直接在压缩包support目录运行。需要既有JDK8及源码构建目录；脚本使用独立随机schema，故障只作用于该测试连接，需要相应建schema/终止测试连接权限。禁止改成终止任意业务会话。每进程30秒看门狗，不自动加压。
3. 客户端在源码根运行tests/run-colleague-regression.ps1，使用隔离构建目录；再登录QA，检查信用最优/利率最优的Bid/Ofr及同档浮层，使用收益率、净价、全价三种输入及T+0/T+1，并核对计算服务日志。
4. 确认计算服务不可用/缺字段时保留原有效收益率，不出现错误零值、不借用估值、不误隐藏报价。
5. 专用测试环境下验证数据库断开后自动恢复及QuoteSvr实例切换后重新同步，记录READY、错误码、请求耗时、实例标识及快照释放日志。
6. QA百万历史SQL仅在获准测试窗口单实例运行；脚本最后ROLLBACK清理，按附带说明回传计时与执行计划。不要把新造数据的热缓存结果当冷启动或并发结论。
