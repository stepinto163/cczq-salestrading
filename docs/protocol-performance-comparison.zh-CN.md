# 协议重构性能对比（2026-09-29）

## 结论与取舍

保留显式应用协议模型，匹配循环不做逐行 JSON／DTO 转换。QuoteMatcher 对一次查询准备条件、按债券缓存基础资料，QuoteFilterValues 按需读取属性与计算价差。性能收益来自减少复制和重复计算，不能简单归因于“DTO 比 JSON 快”。

保留数据库 JSON、通知内部状态和 UI 行投影等实现边界。本次没有为了统一形式继续扩大内部转换。响应编码仍增加成本；若完整查询测量显示其成为瓶颈，应减少重复编码或直接构造类型化响应，同时保持协议定义与业务校验。

## 测试范围

- 用户授权的固定上限：1,000 条报价，无 UI，一个测试进程运行完才启动下一个，外部 15 秒 watchdog；没有扩大压力。
- Java 8，最大堆 128 MB，ActiveProcessorCount=2；8 次预热、20 次采样。
- 同一债券 250001.IB，价格分别为 2.5000／2.7000；条件 BETWEEN 2.4 和 2.6，两版均匹配 500 条。
- 响应编码使用固定的 50 条记录。combined 顺序执行请求解码、匹配和响应编码，未包含真实查询的排序、权限投影、分页、数据库、GW、网络或客户端渲染。
- baseline 使用保留在测试目录的原 JSON 匹配器并绕过新协议转换；typed 使用当前匹配器和协议边界。报价模型在采样前建立，初始化与常驻内存未计入。

## 测量结果

时间单位 ms；分配量为当前线程单次操作平均分配字节，并非常驻堆大小。

| 操作 | 原版 p50 / p95 | 当前 p50 / p95 | 原版分配字节 | 当前分配字节 |
|---|---:|---:|---:|---:|
| 请求解码 | 0.0106 / 0.0342 | 0.0336 / 0.0550 | 1,248 | 4,896 |
| 匹配 1,000 条 | 5.6124 / 8.5449 | 0.4372 / 0.5158 | 8,691,706 | 701,746 |
| 编码 50 行响应 | 0.2663 / 0.5319 | 0.6877 / 1.4109 | 52,256 | 413,096 |
| combined | 7.4778 / 10.7015 | 1.3689 / 2.1459 | 8,870,008 | 1,119,602 |

当前样本支持保留匹配器实现，但不能据此承诺端到端低于 100 ms。单债券有利于每次查询的基础资料复用；多债券、复杂分组条件、持续更新和客户端模型转换还没有在本次对比中测量。短采样也存在 JIT／GC 波动。

## 正确性验证

- TypedFilterEquivalenceTest：覆盖产品字段在旧补充数据和新属性读取器之间的一致性，并检查匹配操作符。
- PostgreSQL 报价生命周期：50 项通过；QTrade 接入及分组：33 项通过。
- PostgreSQL 提醒协议：21 项通过，覆盖四类提醒、已读／未读及偏好。
- Java 实际请求、响应、推送交由 C# 模型读取并往返校验：报价 270 项、提醒 41 项通过。
- `build all` 成功。上述测试不等于 QA 网络端到端验收。
